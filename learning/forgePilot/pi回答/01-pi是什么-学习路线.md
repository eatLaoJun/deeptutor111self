# pi 是什么 · 学习路线

## 一、一句话定位

**pi 是一个极简、可扩展的 agent harness（`README.md`）。** 它把
「模型请求 → 工具执行 → 上下文组装 → 会话存储」这四件事组织起来，
不内置 sub-agent、不内置 plan mode，让你用 extension / skill / prompt template / theme
自己拼。

## 二、能力边界（决定架构的关键）

`docs/how-pi-works.md` 的定义：

> Pi coordinates model requests, tool execution, context assembly, and session storage.
> A session is Pi's record of a conversation...

它**负责**：

- Agent Loop：消息入 active branch → 组装请求 → provider 流式返回 → 执行 tool call → 记录 → 下一轮
- 会话：append-only JSONL，消息与事件构成**树**，active branch 提供上下文
- 上下文：system prompt + 发现的 context files + 工具定义 + skill 描述（skill 正文按需加载）
- 压缩：compaction 插入一条 summary entry 替换老消息，**原始 entry 仍保留在树里**
- 消息队列：steering（当前 assistant turn 之后插入）/ follow-up（整个 run 结束后插入）
- 资源与信任：信任决策后加载项目 settings / resources / context files

它**不负责**（这些必须由平台自己写）：

- ❌ 任务状态机、阶段编排
- ❌ 任务持久化 / 检查点 / 幂等 / 租约
- ❌ 权限模型（只有 OS 权限 + 项目信任，`docs/security.md` 明确说不做沙箱）
- ❌ 任何评估体系（P/R、SWE-bench）
- ❌ 多租户、配额、审计

**这句话是面试的核心立论**：pi 负责"模型—工具循环"，平台负责"阶段、权限、预算、制品"。

## 三、工具集

内置工具（`docs/settings.md` `defaultTools`）：
`read`、`bash`、`powershell`、`edit`、`write`、`grep`、`find`、`ls`

另外 `codemode`、`tool_search` 由内置 extension 注册为 inactive，MCP 工具通过 MCP extension 接入。

> 备注：pi **没有** web 搜索/抓取工具。需要联网时用 `bash` + `curl`。

## 四、推荐学习顺序

| 顺序 | 文档 | 为什么 |
| --- | --- | --- |
| 1 | `docs/how-pi-works.md` | 心智模型：agent loop / 上下文 / 会话树 / 信任 |
| 2 | `docs/usage.md` | 交互界面、`@` 引用文件、`!` 跑命令、消息排队 |
| 3 | `docs/sessions.md` | `--continue`、`/resume`、branch、压缩、导出 |
| 4 | `docs/cli.md` + `docs/cli-integration.md` | 四种驱动模式的区别（这是集成的入口） |
| 5 | `docs/json.md` + `docs/rpc.md` | 事件契约与双向协议（**做平台必读**） |
| 6 | `docs/compaction.md` + `docs/session-format.md` | 压缩语义、JSONL 契约 |
| 7 | `docs/security.md` | 权限与信任边界 |
| 8 | `docs/extensions.md` / `skills.md` / `prompt-templates.md` | 定制层，按需 |

定制机制按"最轻可用"排序，不要一上来写 extension：
`AGENTS.md` → prompt template → skill → extension → TUI → Pi package。

## 五、自定义机制对照表

| 需求 | 用哪个 |
| --- | --- |
| 给某个目录的常驻指令 | `AGENTS.md`（context files） |
| `/` 菜单里的可复用 prompt | prompt template |
| 任务专属说明 + 附带文件 | skill |
| 可执行工具 / 自定义命令 / 事件钩子 | extension（**TypeScript**） |
| 自定义终端组件 | TUI |
| 连接不支持的模型服务 | custom provider |
| 打包分发以上资源 | Pi package |

⚠️ **extension 是 TypeScript 模块，运行在 pi 进程内。** 这是"想用 pi 就必须碰 TS"的唯一入口——
但可以通过 Python 写的 MCP server 绕开（`pi mcp add ticket-tools -- python -m your.module`）。
而且从安全角度，**把外部系统操作放进 pi 进程内本来就不该做**：凭据会进入 agent 进程。
