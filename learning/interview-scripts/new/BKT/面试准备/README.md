## 3. 60 秒项目介绍

> 我在鼎校伴学里做了基于 BKT 的知识点掌握状态更新，解决的是“学生做完题以后，系统怎么判断这个知识点大概会不会”，而不是让大模型直接给学生贴标签。
>
> 我把真实掌握状态和答题表现分开：会的人也可能失误，不会的人也可能答对。离线估计初始掌握、学习转移、猜测和失误参数，在线收到有效作答以后，先根据对错做贝叶斯更新，再考虑练习带来的学习转移，维护每个学生、每个知识点的掌握概率。
>
> 数据稀疏的知识点采用组级参数、父层回退和平滑，但学生状态仍然独立保存。Workflow 负责本次辅导是否达标，BKT 负责跨任务的掌握判断；作答按事件去重回流，提示后做对不当作独立诊断证据。后续推题结合掌握状态、教材进度和题目难度，不是直接挑最低概率的知识点一直练。

## 4. 3 分钟项目介绍

> 这部分的业务动机是，系统不能因为学生说“懂了”，或者刚好做对一道题，就认定他已经掌握。我们还需要把不同学习任务里的作答证据积累起来，给下一次诊断和推题提供依据。
>
> 所以我实现了 BKT 掌握状态更新。它把“是否掌握”作为看不见的状态，把“答对还是答错”作为能看到的观测。模型里有四类参数：初始掌握描述跟踪开始时的起点，学习转移描述一次学习机会后从不会到会的概率，guess 描述不会但做对，slip 描述会但做错。学生当前的掌握概率是递推出来的状态，不是这四个参数中的一个，也不等于下一题的正确率。
>
> 一次在线更新我分两步。先根据本次对错修正判断，例如答对时，要比较“已经会所以答对”和“不会但碰巧答对”两条路径；然后再考虑这次练习可能让原本不会的学生学会。下一次作答就用更新后的概率继续递推，不会每次重置到初始值，也不需要每题重新训练模型。
>
> 离线和在线的职责我也分开了。离线用多个学生的历史序列估计参数，数据按学生和知识点组织，保留时间顺序；在线只拿已发布参数更新当前学生的状态。EM 是这类隐状态模型常见的参数估计方法，它不是把对错次数直接当成 guess 或 slip。我能够解释它的 E 步和 M 步，但不会因为介绍方法就额外声称使用了某个没有确认的训练库。
>
> 在知识点很多、数据不均衡的情况下，我采用了参数分层与平滑。少量数据的知识点借用教学含义相近的组级或父层参数，有足够证据再增加局部估计的权重。这只是共享统计规律，不是把不同学生、不同知识点的掌握状态混成一份。
>
> 工程上，真正难的是证据边界。重复提交不能让同一个答案更新两次；提示后答对、重做原题和首次独立作答也不能混在一起。Workflow 的通过结论表示这次辅导满足规则，不会直接把 BKT 概率改成一。两者不一致时保留各自依据，通过后续变式题或间隔复习补证据。
>
> 最后我把预测能力和教学效果分开看。未来作答预测可以用损失、概率校准和基线对比来评估，但掌握概率上涨本身不能证明学生真的学得更好，仍然需要独立新题、延迟保持和迁移表现。具体效果数字按真实测量结果回答，不用演算示例代替。

## 6. 面试前纠正这十句话

| 不要这样说 | 应该这样说 |
| --- | --- |
| p=0.8，所以下一题有 80% 概率答对 | 掌握概率与答对概率不同，还要考虑 guess 和 slip |
| 答对一次就掌握了 | 答对增强证据，但可能存在猜测、提示或题目过易 |
| learn 是正确率 | learn 是未掌握到掌握的状态转移概率 |
| 四选一，所以 guess 一定是 0.25 | guess 是未掌握时答对的条件概率，不只包含纯随机猜测 |
| 无遗忘，所以概率只会上升 | 无遗忘约束潜在状态；新错误仍可修正此前的高估 |
| 每做一道题就训练一次模型 | 在线更新个体状态，离线估计共享参数 |
| 共用参数，所以学生掌握度相同 | 共用参数不等于共用学生状态 |
| 分层平滑就是严格的层次贝叶斯模型 | 加权收缩是工程近似，不等于联合概率建模 |
| Workflow 通过就把 BKT 改成 100% | 本次任务达标和长期掌握是不同结论 |
| BKT 概率涨了，证明学习效果提升 | 模型增量是代理信号，还需要独立后测 |

## 7. 最后一次脱稿检查

1. 不看材料，画出“参数版本 + 学生知识点状态 + 作答事件”的关系。
2. 用分配律案例解释先验、后验、学习转移，不必背 EM 推导。
3. 说出一次重复提交为什么不能让概率再涨一次。
4. 说出“任务通过但掌握概率仍不高”为什么不矛盾。
5. 被问具体样本量、阈值、评测成绩时，用自己的真实记录，不拿本文示例回答。

练习方式：先用一句话下结论，再讲机制，最后补一个边界。回答卡住就回到对应导学小节，不用堆更多模型名字。
