## 6. 项目技术定位

AI 应用、概率状态建模与后端工程的交叉模块：BKT 维护知识点掌握判断，学习 Workflow 管当前任务推进，题库策略决定下一步练什么。

## 7. 核心原理解析

### 7.1 状态建模：模型里究竟有什么

**问题：** 单次正确率无法说明学生是否真正掌握。

**机制：** 经典 BKT 用两个隐状态“未掌握、已掌握”，对错是观测。它可以表示为二状态隐马尔可夫模型。人的理解程度不是真的只有两档，这是为了可解释递推采用的模型简化。

**项目落点：** 按“学生 + 知识点”维护独立的掌握概率，供后续诊断与推题使用。

| 符号 | 名称 | 条件概率含义 | 不能混成什么 |
| --- | --- | --- | --- |
| L0 | 初始掌握 prior | 跟踪开始时已掌握的概率 | 每一轮重置的初值 |
| T | 学习转移 learn | 未掌握者经过一次学习机会变为掌握的概率 | 正确率或固定加分 |
| G | 猜测 guess | 未掌握时仍然答对的概率 | 必然等于随机选项命中率 |
| S | 失误 slip | 已掌握时仍然答错的概率 | 所有错题中粗心题的比例 |
| p | 当前掌握状态概率 | 根据这个学生已有历史估计当前已掌握的概率 | 离线共享参数或答对概率 |

“guess”可以吸收部分知识、题目线索等影响，不只表示闭眼猜；“slip”是模型中的观测噪声，不是已确认的错误原因分类。

四参数是给状态变化提供规律的模型参数，p 是每个学生的动态状态。在基础模型中，一份知识点组参数可以服务多人，但每个人的 p 不同；同组不同知识点的 p 也不能合并。

### 7.2 在线递推：先修正判断，再考虑学习

**问题：** 一个新答案怎样改变当前掌握判断？

**机制：** 贝叶斯观测更新，再进行状态转移。

**项目落点：** 一次有效作答只递推对应学生、对应知识点的状态，下一次接着使用，不从头重算初值。

#### 时间约定与公式

```text
p_t：本次作答前，基于此前历史的掌握概率
q_t：看完本次对错，尚未计入本次学习转移的掌握概率
p_(t+1)：计入学习转移后，用于下一次作答的掌握概率

预测本次答对：
r_t = p_t * (1-S) + (1-p_t) * G

本次答对：
q_t = p_t * (1-S) / r_t

本次答错：
q_t = p_t * S / [p_t * S + (1-p_t) * (1-G)]

考虑本次学习机会：
p_(t+1) = q_t + (1-q_t) * T
```

答对分母有两条路径：“会且没失误”与“不会但答对”；分子只保留第一条。答错同理比较“会但失误”与“不会且答错”。这就是贝叶斯公式，不是人为给概率加减一个分数。

学习项只作用于“仍未掌握”的部分：已经判断掌握的 q_t 不用再学习，剩下的 `1-q_t` 按 T 转移。

#### 同一个案例的完整演算

以下全部是演算示例：`L0=0.30、T=0.10、G=0.20、S=0.10`。

首次独立作答前，`p=0.30`：

```text
预测答对率 = 0.30*0.90 + 0.70*0.20 = 0.41

若答对：
q = 0.27 / 0.41 ≈ 0.6585
p_next = 0.6585 + 0.3415*0.10 ≈ 0.6927

若答错（从相同初始状态走另一分支）：
q = 0.03 / (0.03 + 0.56) ≈ 0.0508
p_next = 0.0508 + 0.9492*0.10 ≈ 0.1458
```

连续序列“对、错、对”，每一行接上一次的输出：

| 本次结果 | 作答前 p | 预测本次答对率 r | 观测后 q | 转移后 p_next |
| --- | --- | --- | --- | --- |
| 对 | 0.3000 | 0.4100 | 0.6585 | 0.6927 |
| 错 | 0.6927 | 0.6849 | 0.2198 | 0.2978 |
| 对 | 0.2978 | 0.4085 | 0.6562 | 0.6906 |

计算时保留完整精度，表格只在显示时四舍五入。

同样是首次答对，起点 p=0.30 与 p=0.80 的学生更新结果不同，所以 BKT 不是把最近正确次数统一映射成一个分数。

#### 三个容易被追问的点

1. **p 不等于正确率。** 若 p=0.80，预测答对率是 `0.80*0.90+0.20*0.20=0.76`。
2. **无遗忘仍可能下降。** 经典模型不允许隐状态从掌握退回未掌握，但新错误会让系统发现此前可能高估，降低对掌握的信念。学习转移没有保证最终 p 一定比上一轮高。
3. **答错也可能学习。** 练习反馈可能带来学习，但纯测验没有相同学习条件，不能照搬同一个 T。`T=0` 可以作为理解纯观测更新的示例，不是本文给项目指定的配置。

通常希望 `1-S > G`，即掌握者比未掌握者更容易答对。若两者相等，对错就不能区分这两种状态；这是模型质量检查，不是靠随意改几个数就能修好。

### 7.3 训练推断分离：四参数从哪里来

**问题：** 真实掌握状态没有标签，四参数又不能随意指定。

**机制：** 离线用历史作答序列拟合观测似然，在线用参数进行个体状态递推。

**项目落点：** 群体参数与学生状态分开维护，不让在线请求每题跑一次参数拟合。

训练数据按学生和知识点组织：

```text
学生甲 + 分配律：错、对、对、错
学生乙 + 分配律：对、对、错
学生甲 + 移项：错、错、对
```

参数可以共享，但不能把这些序列直接拼成一个学生、一项技能的隐状态轨迹。顺序、题目版本、是否独立作答和提示信息都影响观测是否可用。

拟合目标可以写成：

```text
最大化 Σ_序列 log P(这个对错序列 | L0,T,G,S)
```

EM 是常见求解方法，本文解释其原理，不据此指定项目采用的训练库：

1. 初始化一组参数。
2. E 步：在当前参数下，用前向、后向计算估计各时刻隐状态及状态转移的期望统计量。
3. M 步：利用期望统计量更新初始掌握、学习、guess、slip 参数。
4. 迭代到收敛，注意不同初始化、边界参数和局部最优。
5. 在独立验证集检查未来作答预测，不只比较训练似然。

白话理解：先拿一套参数解释学生可能何时掌握，再根据这些概率解释修正参数，反复进行。不会真的产生一份可信的“学生在哪一题学会”的人工真值。

术语容易撞名：在线过滤只用当前及过去观测；训练中的历史状态平滑可以利用训练窗口内的后续观测；7.4 的参数平滑则是向父层收缩参数。三种事情必须分开说。

评估某次作答时，先用旧状态预测，再吸收本次结果。不能更新完后，用已经看过答案的状态来声称预测准确。

### 7.4 稀疏数据治理：分层共享与平滑

**问题：** 知识点数量多，样本密度不均，少量学生序列无法稳定估出四参数。

**机制：** 有教学含义的组级共享、父层回退，以及局部估计向父层收缩。

**项目落点：** 稀疏知识点先使用更稳定的统计规律，有充分证据后再增加局部差异的权重；学生状态仍独立维护。

层级示意：

```text
学科 -> 章节 -> 教学含义相近的知识点组 -> 具体知识点
```

共享的是参数，不是把全章节的掌握概率都设成同一个 p。也不能为了凑样本，强行共享没有教学关联的知识点。

解释工程平滑时，可以用下面的示意式，不宣称这是生产原样公式：

```text
effective_parameter = w * local_parameter + (1-w) * parent_parameter
w = n_eff / (n_eff + kappa)
```

`n_eff` 表示有效证据量，`kappa` 表示收缩强度。有效证据不能只看原始提交次数，还要看独立学生覆盖、有效观测和序列质量；不同参数需要的统计支持也不同。

演算示例：局部 T=0.30，父层 T=0.10，n_eff=10，kappa=90。

```text
w = 0.10
平滑后的 T = 0.10*0.30 + 0.90*0.10 = 0.12
```

这类加权收缩是工程近似，和在概率模型中设置层次先验、联合推断不是同一方法。平滑可能减少波动，也可能掩盖真实差异，要按稀疏度比较基线，不能宣称必然更准。

新学生主要缺个体历史，从适用的 L0 开始；新知识点主要缺群体参数，向相关组或父层回退。这两个冷启动问题不同。

### 7.5 证据与状态治理：怎样接进项目

**问题：** 数学公式即使正确，重复事件、提示和错误归因仍会让画像失真。

**机制：** 作答证据分流、事件幂等、按顺序递推；任务结论与掌握状态分离。

**项目落点：** Workflow 把合格作答证据回流 BKT，LLM 不直接修改掌握概率，Workflow 也不另算一份长期掌握度。

```text
作答提交
  -> 关联学生、任务、题目、知识点和作答尝试
  -> 校验评分、作答条件与证据是否有效
  -> 按事件 ID 去重
  -> 读取对应参数与当前状态
  -> 按序执行观测更新和学习转移
  -> 持久化新状态与已处理标记
  -> 为下一次诊断、复习和推题提供状态依据
```

以下是帮助面试画图的数据模型，不指定真实表名或数据库选型：

| 数据 | 粒度 | 保存内容示意 | 为什么分开 |
| --- | --- | --- | --- |
| 参数快照 | 知识点或参数组 + 模型版本 | L0、T、G、S、父层来源 | 多个学生复用规律 |
| 学生知识点状态 | 学生 + 知识点 | p、对应参数版本、事件顺序、状态版本 | 独立保存个人历史的递推结果 |
| 作答事件 | 一次正式作答或有效尝试 | 原始答案、评分、提示条件、题目版本、事件 ID | 保留依据，支持去重和必要重放 |
| Workflow 结论 | 一次学习任务 | 达标、需要复习、证据不足及引用 | 表示本次任务结果，不覆盖长期 p |

重点边界：

- 提示后答对、讲解后练习和独立诊断分开，不把前两类无条件送进同一诊断观测模型；使用不同参数或观测模型属于需要验证的扩展。
- 概念复述按量规用于 Workflow 验收，不把模型评语直接转成 BKT 的一次“答对”。
- 重发同一个事件只处理一次；真正的新尝试仍要检查答案曝光和独立性，不是换了事件 ID 就变成独立证据。
- 同一学生知识点的状态更新需要串行化或版本控制，去重检查、状态提交与已处理标记要处于同一可靠提交边界。
- 多知识点题没有可靠步骤归因时，不把整题错误完整更新给所有知识点。
- 迟到事件不能随意追加到序列末尾；应先依据业务顺序规则判断，必要时按规范顺序重放。评分更正同样不能简单覆盖旧对错后继续用旧 p。

已有学习材料明确的链路是证据分流和事件幂等；具体存储字段、乱序重放、评分更正机制在这里作为工程追问解释，不额外指定某套已经上线的技术实现。

### 7.6 选型与评估：BKT 不负责所有事情

**问题：** 掌握状态不能直接代替完整推荐，也不能自己证明教学效果。

**机制：** 状态估计、教学决策、工程服务和评估分别负责。

**项目落点：** BKT 提供目标技能的掌握判断，推题还要考虑教材进度、先修、难度、近期重复与复习需求。

```text
BKT：这个知识点大概会不会？
IRT 等难度模型：这道题对当前能力有多难？
选题策略：当前应该诊断、修复弱项，还是复习？
候选池：怎样让选题服务及时可用？
独立后测：是否真的保持并迁移了所学？
```

经典 BKT 的局限包括：二状态简化、基础模型没有显式遗忘、同组观测参数可能忽略题目难度差异、多技能题归因困难，以及不同参数组合可能解释相近数据。复杂知识追踪模型可以作为演进候选，但不能因为名称更复杂，就断言数据需求、校准或教学效果一定更好。

## 8. 关键设计决策

| 决策 | 备选与取舍 | 风险 | 怎样验证 |
| --- | --- | --- | --- |
| BKT 状态建模 | 正确率基线更简单；BKT 显式表达观测噪声与学习转移 | 参数假设可能不适合题目 | 相同预测时点比较未来作答损失与校准 |
| 离线参数、在线状态分离 | 不在每次在线请求拟合全部参数 | 参数可能随业务漂移 | 分时间窗口、题型和教材范围分析 |
| 组级共享与父层平滑 | 稀疏数据借统计支持，充足数据保留局部差异 | 共享引入偏差 | 分稀疏组、充足组比较直接回退与平滑 |
| 独立诊断证据优先 | 宁可少吸收一些观测，也不把提示做对当成同类证据 | 状态收敛较慢 | 按提示、重做、新题分层看预测误差 |
| 参数与状态留版本 | 不混淆状态所依据的模型 | 新参数直接接旧状态会改变解释 | 升级前定义保留、重放或重新初始化策略 |
| 任务结论和掌握判断分离 | 本次达标不能代表永久掌握 | 产品可能误读为互相冲突 | 检查结论依据，安排变式和延迟验证 |

版本升级是需要明确策略的工程问题：保留旧快照、受控重放或有标记地重新初始化都有取舍。未提供实际升级记录时，不额外声称做过生产重放或零损迁移。

## 9. 量化与验证建议

具体数据未提供，不写数值成绩。以下是能够在面试里解释的评估方法，不把它们全部说成已经完成的实验。

| 验证对象 | 建议方法 | 能回答什么 | 不能推出什么 |
| --- | --- | --- | --- |
| 下一次作答预测 | 时间切分；与近期正确率、简单先验等基线比较 | BKT 是否更好解释未来作答 | 真实掌握状态一定被准确识别 |
| 概率质量 | LogLoss、Brier、校准曲线；AUC 作补充 | 概率是否可靠、排序是否有区分力 | AUC 高不等于概率已校准 |
| 稀疏处理 | 分学生覆盖、知识点样本密度比较 | 平滑是否减少不稳定 | 全局平均好就代表冷启动好 |
| 工程正确性 | 检查重复事件、并发、评分更正与重放一致性 | 同一证据是否只生效一次 | 工程正确就一定预测准确 |
| 教学效果 | 同技能独立新题、延迟保持、迁移题 | 学生是否真正学会并保持 | p 上涨本身证明教学增益 |

预测评估记录的是作答前的 `r_t`，不是作答后的 q 或 p_next。用训练窗口完整序列做 EM 可以，但验证集的未来答案不能参与当时的在线预测。测试新学生泛化时，还需要学生级留出，检查相似题与模板泄漏。

补充公式，理解即可：

```text
LogLoss = -平均[y*log(r) + (1-y)*log(1-r)]
Brier = 平均[(r-y)^2]
```

其中 y 是实际对错，r 是吸收这次答案之前的预测答对率。已掌握隐状态通常没有直接真值，所以不能把预测对错的成绩直接叫“掌握度准确率”。
