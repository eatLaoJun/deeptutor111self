# KingSchool 教练端智能任务平台：轻量可插拔 Agent Harness

更新日期：2026-09-23

## 1. 方案定位

面向 KingSchool 教练端设计一个小型、可插拔的 Agent 任务运行底座，先以“产品使用指引助手”作为首个小型任务，帮助首次使用的教练了解功能、入口、用途和操作流程；之后接入“专题研究与备课助手”，作为首个复杂业务。

核心定位：Harness 提供共同的运行机制，Capability 承载完整业务流程，Tool 完成具体操作，LangGraph 负责流程内部的状态与执行编排。

本文是架构设计与面试准备方案，不代表已经开发、验证或上线。KingSchool 的现有接口、部署条件、权限体系和数据可用性尚待核实。

相关学习资料见：[教研专题研究与备课助手-LangGraph学习与面试方案](../教研专题研究与备课助手-LangGraph学习与面试方案.md)。该文档中的教育业务改造同样属于方案，不是开源项目已有功能。

## 2. 为什么放在教练端

学生端主要围绕错题讲解、知识点辅导、作答反馈与理解验证展开；教练端先解决新教练“不知道有哪些功能、入口在哪、如何使用”的上手问题，再扩展到多步骤、长耗时、需要人工审阅的研究与材料生成任务。

两端可以在权限允许的情况下复用教材知识库、知识点树和题库，但不必混用同一套交互流程。

教练端的业务价值分为两层：先通过产品说明与入口引导帮助教练使用已有功能，再将“明确需求、查找资料、整理内容、核验证据、生成材料”组织成可追踪的复杂任务。

## 3. 架构分层

```text
KingSchool 教练端入口
    ↓
轻量 Agent Harness
    ├─ 上下文装配：身份、数据范围、教材版本、任务资料
    ├─ 能力注册：输入输出协议、执行入口、工具依赖
    ├─ 工具治理：按需挂载、执行端鉴权、超时与失败处理
    ├─ 任务管理：启动、状态查询、人工确认、恢复与取消
    └─ 运行记录：任务进度、调用轨迹、成本和结果引用
    ↓
Capability 业务插件
    ├─ 产品使用指引：首个小型任务，介绍功能、用途、入口与操作流程
    ├─ 专题研究与备课：随后接入的首个复杂业务
    ├─ 学情分析：后续候选
    └─ 分层练习设计：后续候选
    ↓
Tool 工具适配层
    ├─ 产品使用文档检索
    ├─ 功能目录与授权入口查询
    ├─ 教材检索
    ├─ 题库查询
    ├─ 学情数据读取
    └─ 材料存储与导出
```

以上是目标架构。第一版只实现首个业务需要的组件，不预先建设完整通用平台。

## 4. Harness 与 LangGraph 的边界

| 层次 | 主要负责 | 不应重复承担 |
| --- | --- | --- |
| Harness | 身份与上下文、能力注册、工具策略、任务入口、预算和运行记录 | 另一套图调度器和检查点引擎 |
| LangGraph 工作流 | 业务状态、节点执行、条件流转、分支汇总及中断恢复 | KingSchool 的业务权限体系 |
| Capability | 一个业务的输入输出、流程定义与验收规则 | 各自重新实现整套运行底座 |
| Tool | 有明确参数和结果的一次操作 | 自行取得超出任务授权的数据范围 |

Harness 暴露统一的任务启动和恢复入口，内部委托对应工作流执行。具体检查点后端、框架 API 和恢复语义需要在实现时核对文档并测试，不在方案阶段声称已经具备生产可靠性。

## 5. 最小可插拔协议

### Tool：单次操作扩展

建议声明：

- 工具名称与用途。
- 输入 Schema 与统一结果格式。
- 所需权限、允许访问的数据范围。
- 超时设置、是否只读、是否产生副作用。
- 执行入口与可识别的错误类型。

工具执行前由服务端校验身份、范围与参数。Prompt 中的限制和不向模型展示某个工具，都不能代替执行端鉴权。

### Capability：完整任务扩展

建议声明：

- 能力名称、版本和用途。
- 输入 Schema、输出 Schema。
- 依赖工具与权限要求。
- 工作流构建或执行入口。
- 是否包含人工确认，以及预算默认值。

第一版通过代码注册与配置启用实现可插拔，不做插件市场、热更新或运行不可信第三方代码。“可插拔”首先意味着新增业务时遵循统一协议，而不是修改所有底座代码。

## 6. 业务接入顺序

### 6.1 首个小型任务：KingSchool 产品使用指引

面向首次使用或不熟悉系统的教练，回答“有哪些功能、功能有什么用、入口在哪里、下一步怎么操作”。

典型问题：

- KingSchool 有哪些功能？我第一次使用应该从哪里开始？
- 英语阅读 3 合 1 的入口在哪里？
- 英语阅读 3 合 1 的目的是什么，适合什么场景？
- 找到功能后，应该按照什么步骤使用？

建议链路：

```text
识别功能咨询或操作指引意图
    ↓
必要时澄清功能名称、当前页面和使用目标
    ↓
检索产品说明与操作文档，查询当前角色可用的功能入口
    ↓
解释功能用途、使用条件与操作步骤
    ↓
有已验证入口时返回导航 Action，由前端展示并引导进入
    ↓
继续回答使用中的问题
```

回答内容分为“是什么、为什么用、从哪里进入、怎么使用”四部分，按问题选择展开，不必每次输出完整教程。

资料来源应为已审核的产品手册、功能目录、角色权限说明与版本化入口配置。英语阅读 3 合 1 的实际用途、菜单位置、路由与操作步骤尚未核实，本文不预设答案。没有依据时说明缺口或引导联系支持，不编造功能说明和链接。

导航 Action 只负责跳转或展示入口，不默认代替教练提交任务、发布内容或修改业务数据。入口应使用已登记的功能标识，由可信配置映射到实际路由，并检查角色权限。

这个能力可以使用简单的检索问答与导航流程，不为了框架而强行加入规划、人工审批或复杂恢复机制。它首先验证 Capability 注册、工具接入、上下文和前端 Action 的最小闭环。

### 6.2 随后接入的首个复杂业务：专题研究与备课

### 输入示例

> 为人教版八年级“一次函数”准备两课时教学材料，包含先修知识、常见误区、分层例题和课堂练习，保留教材来源供审核。

### 业务流程

```text
需求澄清
    ↓
生成结构化备课计划
    ↓
教练确认或修改 ── 修改 → 修订计划
    ↓ 确认
执行研究子任务
    ├─ 教材与教学目标
    ├─ 先修知识与常见误区
    └─ 例题与分层练习
    ↓
证据覆盖与一致性检查
    ├─ 存在缺口且预算充足 → 定向补查
    └─ 充分或预算耗尽 → 生成材料并标明缺口
    ↓
教练审阅 → 保存或导出
```

动态的是计划内容和子任务集合，不是允许模型任意修改权限与执行边界。存在依赖的任务按顺序执行；独立子任务才考虑并行。

### 预期产物

教学目标、先修知识、重难点、讲解提纲、例题与练习、证据引用、未解决问题和待人工复核项。初版以结构化数据及 Markdown 为主，不以复杂文档排版作为核心目标。

## 7. 状态、恢复与结果一致性

建议区分四类信息：

1. 运行身份：任务标识、用户标识、授权范围，由可信服务端提供。
2. 业务状态：需求约束、计划版本、子任务结果、证据引用、反馈与剩余缺口。
3. 执行信息：工作流关联标识、当前状态、预算消耗、取消标记。
4. 产物索引：最终材料及引用位置，不把所有原始文件复制进共享状态。

需要明确的边界：

- 人工确认绑定任务与计划版本，拒绝过期确认。
- 修改计划后评估旧结果是否仍然有效，避免新旧计划混合。
- 并行结果按任务标识合并，明确去重与冲突规则。
- 等待人工反馈时结束当前请求，后续通过任务标识恢复。
- 恢复可能涉及操作重放；发布、写入等副作用另行设计幂等键和去重机制。
- Checkpoint 是执行进度管理，不等同于长期用户记忆。

## 8. 运行治理的最小范围

### 工具与数据

能力只获得所需工具。教材检索限定版本和学段，学情查询限定已授权班级或学生。模型不得通过参数覆盖可信身份与数据范围。

### 时间与成本

设定任务超时、工具超时、最大补查次数和模型调用预算。达到边界后返回部分结果与缺口，不无限循环。

### 失败处理

区分参数错误、权限错误、临时网络错误和业务无结果。不是所有错误都重试；自动重试应结合操作是否幂等判断。

### 可观测性

记录任务及子任务标识、阶段变化、工具耗时、调用状态、模型用量与证据引用。日志避免记录不必要的学生个人信息与敏感原文。

## 9. 最小实施顺序与验证门槛

1. 注册产品使用指引 Capability，接入已审核的产品文档和功能入口配置，跑通“功能咨询—用途解释—操作说明—导航 Action”的小型任务。
2. 以专题研究与备课作为第二个 Capability、首个复杂业务接入，检验能否复用底座；跑通需求、计划、检索、校验和材料生成，先不追求并行。
3. 加入计划确认与修改，验证新计划确实影响执行结果。
4. 配置持久化并测试重启后的恢复、重复提交和失效确认。
5. 补充预算、权限、失败与引用检查。
6. 根据真实需求考虑学情分析或分层练习设计，不为证明可插拔而提前堆积业务。

待验证用例：

- [ ] 能根据已审核资料介绍 KingSchool 功能与用途。
- [ ] 英语阅读 3 合 1 的入口与操作指引和当前版本一致。
- [ ] 无权限、入口变更或资料缺失时，不返回误导性导航与说明。
- [ ] 导航 Action 正确打开功能入口，不擅自执行业务操作。
- [ ] 正常生成一份可追溯的专题材料。
- [ ] 缺少教材版本时进行澄清。
- [ ] 教练修改计划后，旧结果不会错误混入。
- [ ] 没有资料时有限终止并明确证据缺口。
- [ ] 越权数据请求在工具执行端被拒绝。
- [ ] 持久化配置下重启后能够恢复任务。
- [ ] 重复确认或恢复不会造成重复业务写入。
- [ ] 第二种能力遵循同一协议接入，而不是复制整套底座。

所有用例目前均为待验证。效果衡量可关注需求覆盖、来源正确性、教师修改量、耗时与成本；具体指标需建立基线后测量。

## 10. 面试表达

### 一句话定位

> 面向 KingSchool 教练端设计轻量可插拔 Agent Harness，统一能力注册、上下文和工具治理；先用产品使用指引解决新教练的功能认知与操作导航问题，再接入专题研究与备课，使用 LangGraph 承载复杂任务的规划、人工确认和迭代检索流程。

### 为什么不是普通备课 Workflow？

备课 Workflow 只解决一个业务；Harness 抽取多种业务共用的运行接口和执行约束。第一阶段只有一个能力时，应说明底座仍在验证，第二种能力接入才更能证明扩展设计有效。

### 为什么不是再造 LangGraph？

不重写图执行器。LangGraph 管理业务图的执行，Harness 对接 KingSchool 的身份、数据权限、工具、任务入口和观测需求。

### 和学生端的区别？

学生端以教学互动和理解验证为中心；教练端先提供产品上手指引，再扩展到任务计划、资料组织、证据校验和人工审核。两端可复用数据服务，不必复制交互与编排。

## 11. 简历参考

建议标题：**KingSchool 教练端智能任务平台 | 轻量 Agent Harness**。

当前可作为方案描述：

> 设计面向教练端的轻量 Agent Harness 方案，划分 Tool / Capability 扩展接口与运行治理边界，以产品使用指引作为首个小型任务，并规划基于 LangGraph 的专题研究和备课工作流。

以下表述仅在对应功能完成并验证后使用：

- 运行底座：设计 Tool / Capability 扩展接口，统一任务上下文、能力注册与工具接入，支持业务流程按配置装配。
- 产品使用指引：结合产品文档与授权功能目录，回答功能用途、入口位置和操作步骤，通过结构化 Action 引导新教练进入对应业务。
- 任务编排：基于 LangGraph 实现需求澄清、计划确认、分任务检索、证据校验和材料生成，支持教练反馈后的任务继续执行。
- 执行治理：按任务限定工具和数据访问范围，管理调用预算与失败处理，记录执行轨迹与产物来源。

根据实际完成范围删减，不把学习方案写成生产落地，不预设成本下降、性能提升或用户规模。

## 12. 当前范围与待确认事项

当前只落文档，不修改 KingSchool 或 DeepTutor 的业务代码，不引入运行依赖。

后续需确认：产品手册、英语阅读 3 合 1 等功能的用途与真实入口、角色可见范围，以及备课阶段所需的教材与题库接口、班级数据授权模型、部署与持久化条件和人工验收标准。

坚持“小底座 + 产品使用指引起步 + 备课业务扩展”，暂不建设插件市场、任意代码执行、复杂多租户平台或全自动教学材料发布。
