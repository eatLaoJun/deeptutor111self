# 鼎校伴学：向量检索与 RAG 面试题及口述

> 整理日期：2026-10-13。配套：[原理导学与学习路线](导学-向量检索与RAG.md)。
> 共 20 道主问题、10 道追问，按 5 组复习。每题先读口述，再用自己的教材或 L2 例子复述。
> 已实现业务按完成式表达；BGE-M3、具体索引和参数属于选型知识，未据此新增生产配置结论。
> 排错与优化题给出我的判断方法，不编造真实事故、压测结果或指标提升。

## 1. 项目简介

我在鼎校伴学中使用单机 Milvus 承接教材 RAG 和 L2 任务记忆的语义检索，向量总量最多百万级。教材按年级限定范围，用户任务记忆保持用户隔离，关系库保存记忆的权威版本、状态和证据关联。

## 2. 简历可用摘要

本次抽取五个架构支柱：语义表示、混合召回、检索范围治理、证据一致性、基础设施复用。以下是候选表达，不新增主导、Owner 或具体模型落地等职责主张。

- **语义表示：** 针对教材表述与学生自然语言问题不一致、历史任务难以按原词定位的问题，将教材片段与 L2 任务文本转换为可检索的向量表示，并保留元数据及权威记录关联，使检索能够覆盖语义相关的知识和经历，而不是只依赖字符串相等。
- **混合召回：** 针对语义相关与精确术语命中需求并存的教材问答，组合 Dense 与 BM25 召回，按片段标识去重并通过排名融合、候选重排选择证据，形成召回覆盖与最终排序分工明确的教材检索链路；具体收益仅引用真实评测。
- **检索范围治理：** 针对跨年级教材混淆及用户私有记忆串用风险，将年级和可信用户身份作为检索约束，使教材候选保持业务适用范围、用户记忆保持归属隔离；范围限制不依赖模型自行判断。
- **证据一致性：** 针对向量索引与记忆权威状态可能存在更新时间差的问题，由关系库保存记忆版本、状态和来源，向量召回后按记录标识回表核对，使语义相似度与事实有效性分开处理，保留错误记忆撤回及来源追溯的依据。
- **基础设施复用：** 针对教材与任务记忆都需要语义检索的业务，在单机 Milvus 中承接最多百万级总向量，复用检索服务而非分别维护两套基础设施；不因用户数增长直接引入分布式集群，扩容依据是资源、负载及可用性要求。

## 3.1 第一组：向量表示与模型选型

### Q01. 为什么选 1024 维？是不是越大越好？

我先把维度和数据条数分开。维度是一条向量包含多少个数，不是有多少条教材，也不是模型能读多少 Token。我的教材和 L2 需要语义相关性检索，所以应先看候选 Embedding 模型实际输出的表示，再让 Milvus 向量字段匹配。1024 维是常见候选，但不能从百万条数据推出必须用这个维度。维度更大通常增加存储和距离计算开销，质量却还受模型、切分和查询表达影响。我会在固定教材、任务记忆和问题集上比较证据召回与资源成本，选择满足目标的配置，不只比较数字大小。更换维度时还要重编码数据和重建索引，因此不是线上随时拧一下参数就能完成。

参考：[Milvus 稠密向量](https://milvus.io/docs/dense-vector.md)。

### Q02. Embedding 模型怎么选？为什么不能只看榜单？

我选模型时先看业务问题，而不是只看通用榜单。教材问答同时有口语化提问、准确术语、公式相关表述和长段落，L2 则是任务经历与短查询匹配，所以候选模型要在这些场景中分别比较。我的评估维度包括中文和教育内容适配、可接受的输入长度、召回质量、查询编码延迟、部署资源、调用成本和版本稳定性。榜单可以帮助缩小候选范围，但不能证明对我的教材一定更好。我会固定切分、过滤条件与检索策略，再比较模型；之后再做完整链路评估，避免把切分或重排变化的收益归给模型。最终我需要的是在现有资源下找得到正确证据，而不是一张最高分榜单。

### 追问 A1. 两个模型都是 1024 维，可以一个负责入库、另一个负责查询吗？

我不会只根据维度相同就混用。1024 只是数组长度，两个模型学习的坐标含义可能完全不同，同一个文本的表示也不一定在同一个可比较空间。我的教材和记忆检索需要查询向量与文档向量兼容，通常采用同一模型版本及匹配的编码配置。如果模型要求查询和文档使用不同指令或输入类型，我会按官方约定处理，而不是把两边文本处理成完全一样就认为正确。若要换模型，我会先建立新表示并评估，不能把新查询直接打到旧索引上。这样可以避免数据库没有报维度错误，业务召回却已经悄悄失效的情况。

### Q03. BGE-M3 的特点是什么？为什么会考虑它？

如果考虑 BGE-M3，我主要看它能覆盖哪些检索需求。三个 M 指多语言、多功能和多粒度，不是三种模态。它支持 Dense、learned sparse 和 ColBERT 式多向量检索，Dense 输出为 1024 维，最长输入能力是 8192 Token。对我的教材和任务记忆，它可以作为长短文本匹配的候选，但这些能力不等于中文教育检索一定最好，也不等于我必须启用全部输出。我会先把 Dense 与其他候选模型放在同样的评测条件下比较，只有某种额外检索模式能带来可验证的收益，才考虑增加对应索引和维护成本。实际项目采用哪个模型要按真实配置回答，不能因为学习了 BGE-M3 就说线上已经使用。

参考：[BGE-M3 模型卡](https://huggingface.co/BAAI/bge-m3)、[M3 论文](https://arxiv.org/abs/2402.03216)。

### 追问 A2. BGE-M3 已经有 Sparse，还需要 BM25 吗？

我会先区分两种稀疏表示的来源。BGE-M3 的 Sparse 是模型为词项生成学习到的权重，BM25 则主要根据词频、文档频率和长度统计评分，它们不是同一种算法。支持 Sparse 只能说明可以做词项交互，不能证明传统 BM25 在当前教材里已经没有价值。我的判断方法是把 Dense、Dense 加 BM25、Dense 加 learned sparse 放到同一问题集和过滤条件下比较，同时记录编码、存储、检索与维护成本。如果新增一路没有稳定补充证据，我不会为了凑齐模型功能把链路越堆越长。是否替换 BM25 是业务评测结论，不是由模型名称直接决定的。

### Q04. 更换 Embedding 模型时，已有数据怎么处理？

我会把换模型视为一次检索表示迁移，而不是简单改 API 名称。即使新旧模型都是 1024 维，也可能不在同一向量空间；如果输出维度不同，向量字段规格还会直接不匹配。我会根据已有教材和 L2 权威文本重新生成向量，建立新 Collection 或独立字段及索引，并把模型版本和索引版本纳入管理。迁移期间要考虑增量更新，避免新索引建好时又落后于业务写入。切换前，我会用固定问题集对比召回、过滤正确性、资源与延迟，保留可回退的旧版本。这样保证切换的是一套一致的文档和查询编码，而不是新查询向量去比较旧表示造成隐蔽错误。

## 3.2 第二组：BM25、融合与重排

### Q05. BM25 是什么？词频、IDF、k1 和 b 怎么理解？

我把 BM25 理解为词项相关性评分，而不是一个神经 Embedding 模型。文本先经过分析器生成词项，倒排索引帮助找到含有查询词的候选，再由 BM25 排序。词频描述一个词在当前片段出现多少次，IDF 描述它在整个语料中是否稀有，文档长度归一化则避免长片段仅靠词多占优势。词频收益会饱和，重复很多遍不会无限加分；k1 控制这种饱和关系，b 控制长度归一化程度。在我的教材检索里，它适合补知识点名称和篇名等词项信号，但同义表达、OCR 和分词错误会影响结果。我会结合实际文本分析和问题集调整，不把某个实现的默认参数当成所有场景的最佳值。

参考：[BM25 原理](https://nlp.stanford.edu/IR-book/html/htmledition/okapi-bm25-a-non-binary-model-1.html)。

### 追问 B1. 中文 BM25 有什么坑？公式和题号一定能命中吗？

我不会认为用了 BM25 就天然支持中文术语和数学公式。它依赖分析器产生的词项，中文不能默认只按空格切分，同一个知识点被拆成不同词项会直接影响匹配。公式还有负号、上下标、括号和 OCR 识别问题，题号也可能只在某份讲义内部有意义。我会检查索引端和查询端的分析方式是否兼容，保留必要的术语、标题及规范化表示；对准确编号，可以使用带讲义范围的结构化字段定位。失败时先看词项和原文有没有被正确保留，再决定是否调整词典、同义词或查询处理，不能仅通过增加返回条数掩盖数据问题。

### Q06. 已经有向量检索，为什么还要 BM25？

我在教材检索中同时面对两类问题：学生可能用口语描述困惑，也可能直接问一个课文标题或明确术语。Dense 能覆盖换一种表达的语义相关性，但整体语义相近的片段未必包含所问对象；BM25 能提供直接的词项信号，却可能漏掉没有相同词的同义提问。因此我使用两路候选互补，再统一去重和排序，而不是让 BM25 替代向量检索。两路都必须限制在正确年级及教材范围内，否则混合只会合并更多不适用材料。效果我会按口语化、准确术语等问题类型分开看，关注新增证据是否真的补了单路缺口，不把两路数量相加就当成质量提高。

### Q07. 为什么用 RRF？能不能把两路分数直接相加？

我使用排名融合，是因为向量相似度和 BM25 原始分数的量纲、范围及分布不同，未经校准直接相加，容易让数值较大的一路支配结果。RRF 根据候选在各路的名次累加贡献，不直接比较原始分数；同一教材片段在两路都靠前，通常会获得更多贡献。融合前要以稳定片段标识对齐记录，不能把同一片段重复当作两个证据。我也不会说 RRF 在所有场景都最好，如果有可靠的分数校准和开发集，可以评估加权融合。我的取舍是先用能解释、易评估的方案解决异构分数问题，再依据真实排序表现决定是否增加调参复杂度。

参考：[Milvus RRF](https://milvus.io/docs/rrf-ranker.md)。

### 追问 B2. RRF 的 k 和 Top K 是同一个参数吗？

我会把这几个参数分开讲。RRF 公式中的 k 是平滑参数，调节前后名次之间的贡献差异，不表示最终要返回多少条记录。Dense 和 BM25 各自召回多少条，是候选覆盖与检索开销的选择；融合后重排多少条，是模型计算预算；最终放进上下文的 Top K，又受证据质量和生成窗口影响。比如增加某一路候选，并不等于增加最终上下文，也不等于应该同步改大平滑参数。我会分别记录各阶段数量和业务指标，检查重复、无效候选与证据漏召回，再逐项调整，避免把多个叫 k 的参数混成一个总开关。

### Q08. Rerank 与 Embedding、RRF 的区别是什么？

我把它们放在不同阶段。Embedding 通常先独立编码查询和文档，再快速比较表示；RRF 只利用多路结果的名次做融合，不重新理解正文。语义 Rerank 则对已经召回的有限候选进一步评分，常见 Cross-Encoder 会联合读取问题和候选文本，判断谁更能回答当前困惑。教材里提到去括号不代表解释了为什么变号，重排就是进一步区分这类同主题材料。代价是额外推理、排队和调用成本，所以我只重排有限候选，而不是扫描全库。它能调整已有候选的顺序，却无法补回候选集合之外或知识库里缺失的证据，超时可回退到已过滤的融合排序。

参考：[Retrieve & Re-Rank](https://www.sbert.net/examples/sentence_transformer/applications/retrieve_rerank/README.html)。

## 3.3 第三组：切分、度量与范围治理

### Q09. 教材 Chunk 怎么切？为什么不能越长越好？

我切教材时先考虑证据完整性，而不是机械每隔固定字符截断。定义、规则、例题步骤和结论如果被拆散，召回了某一段也可能回答不了问题；但片段过长，又会混合多个知识点，增加编码、重排及最终上下文开销。我会先保留章节和小节边界，超长内容再按段落或句子切分，并把简短标题路径与正文一起作为可理解的内容。重叠可以保留边界信息，但也会带来重复候选，要注意去重和覆盖。最终我会结合固定问题集比较证据命中、重复率与成本，而不是因为模型支持长输入就把整个章节甚至整本教材编码成一条向量。

### 追问 C1. BGE-M3 支持 8192 Token，是不是 Chunk 就切成 8192？

我不会把输入上限直接当作推荐切分长度。8192 Token 描述的是模型能力边界，不是中文字符数，也不是生成模型或重排模型都能用的统一预算。一个片段还可能拼接章节标题和其他上下文，实际编码输入要整体计算。教材检索需要定位能够支撑回答的证据，过长片段可能把相关内容稀释到多个主题里，最终重排也可能因为长度限制截掉关键部分。我会在模型允许范围内选择能保留定义、推导或例题语义的粒度，并根据评测调整；只有长片段确实提高证据覆盖且成本可接受，才采用更大的输入，而不是为了用满模型能力上限。

### Q10. COSINE、IP 和 L2 怎么选？归一化有什么作用？

我先看模型建议使用哪种相似度，再让编码和索引设置匹配。余弦相似度主要比较方向，内积同时受方向和向量长度影响，L2 衡量两点之间的距离。对非零单位向量，内积等于余弦，平方 L2 与余弦也有确定的反向关系，所以精确排序可以一致；对没有归一化的表示，就不能直接套这个结论。归一化是把向量的范数变成一，不是把每个数压到零到一之间。在 Milvus 中还要注意 L2 返回平方距离，数值越小越近，COSINE 和 IP 则通常越大越近。我会检查实际返回分数的定义，避免阈值方向写反，也不把相似度当成学生掌握概率或回答正确概率。

参考：[Milvus 度量](https://milvus.io/docs/metric.md)。

### 追问 C2. 余弦相似度 0.8，是不是代表 80% 相关或正确？

我不会这样解释。余弦分数描述模型表示中的角度关系，不是校准过的正确概率。两个片段很相似，也可能属于不同年级、不同教材版本，甚至只是都包含同一个错误例子，不能因为分数高就当成可用答案。同样，不同模型、片段长度和问题类型的分数分布也可能不同，不能把一个模型的阈值直接搬到另一个模型。我的做法是先保持业务范围正确，再结合标注问题观察分数与证据有效性的关系，评估阈值带来的漏召回和错误使用。对候选不足或证据不完整的情况，我会澄清或明确不足，不把高分当成可以强行回答的授权。

### Q11. 元数据过滤为什么重要？是不是有向量索引就不用标量索引？

我的教材与用户记忆都有明确适用范围，语义相近不能替代年级正确和用户归属。所以我把教材年级、可信用户身份及必要状态条件传入检索请求，在允许范围内取候选，而不是让模型事后判断哪些数据能用。向量索引帮助找相近表示，标量索引帮助处理非向量字段的条件，它们职责不同；写了过滤表达式不代表字段已有索引，建了索引也不代表请求自动带上权限。对常用条件，我会评估基数、查询分布和索引开销，不盲目给每个字段建索引。BM25 路与缓存也必须保持同样的范围约束，否则向量路安全，另一条路仍可能引入不适用材料。

参考：[Milvus 过滤检索](https://milvus.io/docs/filtered-search.md)。

### Q12. Database、Collection、字段和索引分别是什么？

我会先把逻辑层级讲清楚。Milvus 实例里可以有 Database，Database 里有 Collection，Collection 定义主键、文本、元数据和向量等字段；向量维度是稠密向量字段的规格，而不是整个实例统一的设置。向量索引和标量索引则分别服务相似度检索与条件过滤，不是 Collection 的别名。在我的项目里，教材和 L2 都使用向量服务，但权威记忆版本及来源关联仍由关系库管理。若按用途划分 Collection，可以分别管理模型、索引与生命周期，这是组织方式的取舍，不意味着每个用户都应创建一张 Collection。我不会把关系库的联合索引规则原样套到向量索引上，也不会因为有过滤字段就说完成了数据隔离。

## 3.4 第四组：近邻索引与单机容量

### Q13. 为什么需要 ANN？FLAT 与 HNSW 有什么区别？

我需要先区分精确近邻与近似近邻。FLAT 在指定范围里逐条计算距离，可以作为精确基线，但候选多、维度高、并发上来后计算开销会增加。ANN 用可接受的近邻遗漏换取更低检索开销，HNSW 是其中一种基于多层邻近图的算法，不是 ANN 的全部。它通过图上的导航减少不必要的距离比较，但要维护图结构，增加内存与构建成本。我的项目同时有教材查询和强用户过滤的 L2 查询，不能只按总量选索引。我会在真实范围内用精确结果对照近似结果，再检查业务证据是否命中；索引找到模型最近的记录，也不代表这些记录就能正确回答教材问题。

参考：[Milvus HNSW](https://milvus.io/docs/hnsw.md)。

### 追问 D1. 每个用户最多几千条，为什么还需要 Milvus？

我认为单用户规模小，只能说明该用户的业务候选集有限，不能说明系统只管理这一小份数据。我的服务要管理全体用户的 L2、教材向量、持续写入、过滤和版本关联，两类业务还复用了同一向量基础设施。对某个用户几千条记录，精确计算距离可能就足够，没必要为了所有查询都走图索引而增加复杂度；但这与是否需要一个统一管理和查询服务是两个问题。我会分别判断查询算法和基础设施取舍，避免把单用户记录数当成全库资源需求。现在采用的是单机部署，不是为了几个用户维护一个大型分布式集群，因此从已知规模看有合理的工程依据。

### Q14. HNSW 的 M、efConstruction 和 ef 分别控制什么？

如果评估 HNSW，我会区分建图参数和在线搜索参数。M 影响图中节点的连接数量，增加它通常需要更多图资源，也会影响构建及更新成本；efConstruction 控制建图阶段探索的候选范围，搜索更充分可能得到更好的图，但构建开销也更大。ef 则控制查询阶段的搜索范围，调大通常有机会改善近邻召回，同时增加在线计算。它们都不是最终返回的 Top K，也不是最大并发用户数。我会固定语料、模型、硬件和过滤条件，逐项比较 ANN 质量、业务证据命中、延迟和内存，不直接抄一个万能配置。调 ef 也不能修复教材缺失或 Embedding 已经表达错误的问题。

### Q15. IVF_FLAT 与 IVF_PQ 是什么？什么时候考虑 PQ？

如果比较 IVF，我先看它通过分簇缩小搜索范围的机制。IVF_FLAT 先训练聚类，把向量组织到不同簇，查询时选部分簇，再对簇内原始表示计算距离；nlist 是分簇数量，nprobe 是查询访问的簇数量。少查簇可能漏掉真正近邻，多查簇则增加计算。IVF_PQ 进一步对向量分段量化压缩，减少存储和部分计算开销，但引入量化误差和训练、调参成本。我的项目如果内存确实成为限制，才会评估压缩是否值得，不因为百万级总量就默认采用 PQ。验证时既要看近邻结果的损失，也要看教材或 L2 有效证据是否因此遗漏，不能只报内存少了多少。

参考：[IVF_FLAT](https://milvus.io/docs/ivf-flat.md)、[IVF_PQ](https://milvus.io/docs/ivf-pq.md)。

### Q16. 百万级向量为什么选单机 Milvus？性能会过剩吗？

我的 Milvus 总量最多百万级，其中讲义教材十几万条，L2 任务记忆几十万条，单用户最多大几千条。教材按年级过滤，记忆按用户限制范围，因此不能把每次查询都当成无条件全库搜索。我复用了单机向量服务，没有仅因为有几千用户就引入分布式集群。从这个架构和规模看，单机选型有合理依据，但是否满足峰值负载还要看维度、索引、机器资源、并发和可用性要求。性能有余量不是过度设计，不必要的资源和维护成本才是问题。过滤也不会消除整库存储与索引开销，所以我会明确容量口径，而不是用单用户几千条推断整个服务几乎不占资源。

参考：[Milvus 部署架构](https://milvus.io/docs/main_components.md)。

### 追问 D2. Collection、Partition、分片和副本怎么区分？

我会把数据组织和资源扩展分开。Collection 是记录与字段的逻辑集合，Partition 是集合内的一种数据组织方式，不等于一台独立机器；分区键也不能自动替代权限校验。分片是把数据或工作量拆开，副本是复制数据以支持容错或读分担，它们都不能保证吞吐线性增长。我的项目当前确认的是单机，不会把尚未采用的分片、副本或每用户分区说成已经落地。若未来要扩展，我会先判断是容量、查询吞吐还是可用性受限，再评估组织方式及迁移成本。按用户过滤的候选少，也不意味着应给每个用户创建 Collection，否则管理与资源负担可能反而增加。

## 3.5 第五组：评测、一致性与排错

### Q17. Recall@K、Hit@K、MRR、nDCG 与 ANN Recall 有什么区别？

我会先说明评测对象。ANN Recall 对照同一模型、同一范围下的精确近邻，检查索引有没有漏掉近邻；业务 Recall 则对照人工标注的相关证据，检查答案依据是否找回，两者不能混用。单题 Recall 是前 K 命中的相关证据数除以全部相关证据数，Hit 只判断是否至少命中一个。每题只有一个金标准时，数值可能相同，但多证据问题就不同。MRR 关注第一个相关结果出现的位置，nDCG 还可以考虑不同相关程度与排序位置。我会分别报告候选覆盖、最终排序和回答证据支持，明确多题汇总方式，不把相似度或检索命中率写成最终回答正确率。

### 追问 E1. 混合检索和重排各自贡献多少，怎么证明？

我会通过逐项消融来区分贡献，而不是把完整链路的提升归给最后接入的组件。首先固定语料版本、切分、问题集、模型与过滤条件，分别比较 Dense、BM25 以及融合后的候选覆盖；随后在相同候选集合上比较是否增加语义重排的排序质量。调参使用开发集，最后在独立测试集上复核，并按口语化、术语、长文本等类型检查是否只改善了一小类问题。重排可以提升最终前 K 的证据排序，却不会增加其输入候选集合的覆盖。没有保留独立实验结果时，我只解释机制和完整链路结果，不临时编造某个组件贡献了多少百分点。

### Q18. 检索结果不好，怎么判断是模型、索引还是语料问题？

我会沿链路排查，而不是一开始就换模型。先确认知识库里有没有所需证据，OCR、公式和切分有没有保留完整；没有入库的知识，无论调哪个索引都找不到。再检查年级、版本和用户范围是否正确，过滤过窄可能漏证据，过宽又会混入不适用材料。接着查看 BM25 的词项分析、Embedding 编码和版本兼容性，用同范围精确搜索对照 ANN，判断是不是索引漏近邻。最后检查融合、去重、重排和生成阶段，看正确证据有没有被排序或裁剪丢掉。如果候选已经充分而回答仍错误，我会检查上下文组装和生成，不把所有问题都归因于向量库性能。

### Q19. L2 同时在关系库和 Milvus，怎么保证状态一致？

我的记忆采用权威记录与检索索引分工。关系库保留 L2 内容、版本、有效状态和来源关联，Milvus 负责语义候选，所以向量命中后还要按稳定记录标识回表核对。这样相似但已撤回、版本过旧或不在当前范围的记忆，不会直接当作有效事实使用。两套存储不能因为都写入成功就被当成同一个事务，我通过已有异步同步机制处理索引更新，并需要考虑幂等、重试和状态可见性。索引失败时保留权威记录与重试依据，不能报告语义索引已经可用；内容改动后要同步重编码和版本信息。最终我把向量库当成可重建的检索层，而不是唯一的记忆事实源。

### 追问 E2. 用户撤回或删除记忆，删除关系库记录就够吗？

我不会只删权威记录就认为全部完成。撤回或删除要传播到向量索引和可能的检索缓存，避免旧文本仍被召回或直接复用。即使异步传播尚未结束，回表时也应因为记录不存在、状态失效或版本不匹配而排除该候选，但回表只是额外防线，不是可以长期保留旧索引的理由。缓存键与失效策略还要考虑用户作用域和内容版本，不能让上一轮结果绕过新状态。对失败同步，需要可重试、可观测的处理位置，并限制旧事实继续进入上下文。我的目标是让有效性、检索可见性和证据来源一起收敛，而不是只让一次数据库删除操作返回成功。

### Q20. RAG 响应慢怎么办？哪些地方能降级？

我会先分段测量查询处理、Embedding、Dense 和 BM25 检索、融合、重排以及生成耗时，也关注网络和排队，而不是看见用了 Milvus 就认为慢在向量库。模型编码或重排慢，需要分别考虑输入长度、候选规模、受控批处理和缓存；检索慢，则检查过滤字段、索引、资源竞争与真实流量。任何优化都要同时看证据质量，不能单纯减少候选换一个更快的数字。重排超时可以回退到已有范围内的融合排序，记忆索引不可用时可走关系库的结构化查询。降级不能取消用户隔离或换用其他年级材料；可靠证据不足时，我会澄清或明确不足，而不是为了保持响应速度强行生成答案。

### 追问 E3. 单用户有一万条 L2，或 RAG 范围一万条，召回到底要多少毫秒？

我会先明确计时口径。L2 和教材向量已经入库，在线只对查询编码，不重新处理一万条历史。
纯向量搜索是一个数据库调用；完整记忆检索还包含查询 Embedding 和批量回表，RAG 若先调用模型重写，
还会增加等待完整改写结果的时间，混合检索与重排则另算。单用户一万条也不等于全库只有一万条，
用户过滤、索引、机器与并发都影响实际耗时，不能仅凭条数保证 20ms。

用于解释量级的假设例子：Embedding 100ms、向量搜索 20ms、回表 10ms，则记忆检索是 130ms；
重写 500ms 加 Embedding 与单路搜索，则 RAG 是 620ms；再并行 BM25、融合并重排，示例约 825ms。
这些不是本项目线上指标，也不含最终回答生成。具体性能应给出实际负载下各阶段及完整链路的 P50/P95，
同时说明召回质量；没有留存统计时，只解释分段和预算，不把示例报成实测。

计算与计时边界见[导学 9.5：一万条范围下的查询耗时](导学-向量检索与RAG.md#95-一万条范围下的查询耗时分段口径与计算示例)。
