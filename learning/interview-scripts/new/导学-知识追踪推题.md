## 7. 核心原理解析

### 7.1 状态建模：BKT 到底做什么

问题：只有对错记录，如何判断学生是否掌握知识点？

机制：把“会/不会”作为隐状态，把“对/错”作为观测，用概率连接二者。经典 BKT 可表示为二状态隐马尔可夫模型。[S1]

本方案落点：维护每个学生、每个知识点的当前掌握概率，再供选题策略使用。

#### 整体链路

```text
历史作答序列
    -> 离线估计组级 BKT 参数 -> 发布模型版本

新作答 -> 校验评分与事件去重
    -> 更新相应知识点的 BKT 状态
    -> 更新相应学科/维度的 IRT 能力估计
    -> 增加画像版本，触发候选池补充

请求下一题
    -> 获取教材、进度、目标知识点与当前画像
    -> 读取可用候选池；不足时走受限兜底
    -> 最终过滤、必要重排、原子预占
    -> 返回题目与推荐理由

异步补池
    -> 多路生成 -> 合并、去重、过滤
    -> 初步排序 -> 版本条件提交 -> 写入候选池
```

这是教学性设计，不代表仓库已有对应接口。

#### 四参数

| 参数 | 含义 | 不是什么 |
| --- | --- | --- |
| prior，记为 L0 | 开始跟踪该技能时已掌握的概率 | 每答一道题都重新赋的初值 |
| learn，记为 T | 未掌握者经过一次学习机会转为掌握的概率 | 答对概率 |
| guess，记为 G | 未掌握状态下仍答对的概率 | 必然等于四选一的 0.25 |
| slip，记为 S | 掌握状态下仍答错的概率 | 所有错题中粗心题的比例 |

四参数描述初始状态、转移与观测。它们不是四个简单历史占比。[S1]

“会/不会”是模型的简化，不是说人的理解程度真的只有两档。

#### 参数与状态必须分开

```text
知识点组 A 的参数：L0、T、G、S
学生甲的分配律状态：p = 0.30
学生乙的分配律状态：p = 0.80
```

共享参数不意味着学生状态相同；同组技能也不必共用一个掌握状态。pyBKT 的个体状态维护与模型参数是可区分的概念。[S2]

#### 三步更新公式

设 p 是本次作答前的掌握概率，q 是结合本次观测后的判断。

第一步，预测本次答对概率：

```text
P(答对) = p * (1-S) + (1-p) * G
```

两条路径：“已经会且没失误”与“不会但答对”。

第二步，根据对错做贝叶斯更新：

```text
如果答对：
q = p * (1-S) / [p * (1-S) + (1-p) * G]

如果答错：
q = p * S / [p * S + (1-p) * (1-G)]
```

第三步，考虑本次学习机会带来的转移：

```text
p_next = q + (1-q) * T
```

这组式子由四参数假设、贝叶斯公式和全概率公式得到。直觉是“先修正会不会的判断，再考虑练习带来的学习”。BKT 的状态与转移计算可对照 [S1]；不同实现输出的时间位置可能不同，使用时需明确是观测后还是转移后。

#### 一次完整手算

教学设定：L0=0.30，T=0.10，G=0.20，S=0.10。

```text
本次答对概率 = 0.30*0.90 + 0.70*0.20 = 0.41

如果答对：
q = 0.27 / 0.41 ≈ 0.6585
p_next = 0.6585 + 0.3415*0.10 ≈ 0.6927

如果接下来再次答对：
q ≈ 0.9103
p_next ≈ 0.9192
```

另一条分支：如果从初始 0.30 开始就答错：

```text
q = 0.03 / (0.03 + 0.56) ≈ 0.0508
p_next = 0.0508 + 0.9492*0.10 ≈ 0.1458
```

以上为公式推导，不是学生实测数据。

为什么答错之后也加学习项？因为答错后也可能通过反馈学到东西。若是纯测验、没有学习机会，不应不加区分地套用练习场景的转移参数。

#### 两个高频误区

经典无遗忘设定没有“已掌握 -> 未掌握”的显式转移，但后验概率仍可下降。原因是我们发现之前可能高估了学生，而不是潜在状态一定发生了遗忘。[S1]

掌握概率不等于答对概率。假设 p=0.8、G=0.2、S=0.1，则预测答对率是 0.76，而非 0.8。这是上述公式的直接计算。

#### 为什么不直接用最近十题正确率

方案比较：正确率可以作为透明基线，但不能显式拆分猜测、失误与学习转移。BKT 可以表达这些假设，代价是参数更难估、假设可能不适合实际题目。没有数据比较时，不能断言 BKT 一定更准。

### 7.2 稀疏数据治理：训练、分层与平滑

问题：上千个知识点并不意味着每个知识点都有足够学生序列。

机制：离线用群体序列拟合参数；小样本组共享或借用父层信息；线上递推个体状态。

本方案落点：先保证粗粒度参数稳定，再让证据充分的局部估计发挥作用。

#### 历史数据需要哪些信息

建议记录学生、题目及其版本、知识点映射、事件顺序、对错、是否独立完成、提示使用、尝试次数和评分可信度。

按“学生 + 知识点”组织 `错、对、对、错` 等序列。不能把学生甲的最后一题接到乙的第一题后。即使同组共享参数，也不要把不同技能的状态序列无条件拼成同一隐状态轨迹。

多知识点题存在归因问题：一处计算错误不等于所有技能都不会。初版可优先使用单一主技能题；复杂题有可信步骤评分时再更新对应技能，否则保留不确定性。此处是方案取舍。

#### 怎么训练

最大似然的目标可以写成：

```text
最大化所有训练序列的 log P(对错序列 | L0,T,G,S)
```

一种常见拟合方法是 EM，pyBKT 作者论文描述了前向/后向计算与参数更新。[S1]

1. 初始化参数。
2. E 步：根据训练序列与当前参数，估计隐状态和转移的期望统计量。
3. M 步：利用这些期望统计量更新参数。
4. 反复迭代至收敛，考虑多次初始化。
5. 在独立验证集检查预测与校准，而非只看训练似然。

白话：先暂时相信一套参数，推测学生每个时刻会不会；再利用这些推测修正参数，重复进行。

线上新作答只做状态递推，不必每题重跑 EM。离线训练可用训练窗口内完整序列；在线预测只能用当时已经出现的作答，不能把利用未来信息的历史平滑结果伪装成实时预测。

#### 分层示例

```text
数学
    -> 方程章节
        -> 等式变形知识点组
            -> 具体知识点（证据充分才考虑独立参数）
```

“组”应有教学含义，不要为了凑样本混合无关技能。这里的层级是自定义参数治理方案，不是标准 BKT 自动生成的结构。

一种工程平滑示例，对四个参数分别处理：

```text
effective = w*local_estimate + (1-w)*parent_estimate
w = n_eff / (n_eff + kappa)
```

n_eff 为有效证据量，kappa 控制收缩强度。它们应考虑独立学生覆盖、参数类型和验证表现，不应简单照搬原始作答次数。

教学算例：局部 learn=0.30，父级 learn=0.10，n_eff=10，kappa=90。

```text
w = 0.10
平滑 learn = 0.10*0.30 + 0.90*0.10 = 0.12
```

这个加权公式是可讨论的工程近似，不应称为已经实现的联合层次贝叶斯估计。严格层次模型可以在概率参数上设置父层先验并联合估计，两者实现与统计含义不同。

#### 必须承认的边界

- 冷启动知识点可回退到父层参数，新学生从合理先验与诊断题开始。
- 参数可辨识性可能不足，不同参数组合能解释相似序列。
- 通常希望 `1-S > G`，即掌握后更可能答对；约束仍需验证。
- 分层共享会引入偏差，应分稀疏组、充足组比较。
- 参数版本升级时，要定义旧状态保留、迁移或历史重放策略。
- 看提示后做对与独立首次作答不是同一种证据；重复提交也不能重复更新。

这些是基于模型假设提出的工程风险检查项，不是原材料已解决的结果。

### 7.3 能力与难度：IRT/MAP 如何配合

问题：知道学生分配律薄弱，还不能决定哪一道分配律题难度最合适。

机制：IRT 描述能力与题目属性如何影响答对概率；MAP 是带先验的参数估计方法。

本方案落点：BKT 辅助决定练什么，IRT 辅助决定多难。这是模块化组合，不是已经建立了统一概率模型。

#### 最简单的 1PL/Rasch

```text
P(答对题 i | theta) = sigmoid(theta-b_i)
sigmoid(x) = 1 / (1+exp(-x))
```

theta 是能力，b_i 是题目难度，两者需在同一标尺。theta=b_i 时，该模型预测正确率 0.5。Rasch 与基于 Fisher 信息的选题在教育测量中有实际应用，可对照 Stanford ROAR 技术手册。[S3]

本文以下 MAP、难度反推与信息量公式均是在明确的 1PL 和正态先验假设下进行的教学推导。

不要把数学和英语共用一个能力标尺；整门学科用单一 theta 也是需检验的简化。

#### 难度标签不是已校准的难度参数

“简单、中等、困难”是序数标签，不天然等于 b_i。

教学性初始化可以映射为 -1、0、1，但必须说明未校准。更明确的难度先验可以写成：

```text
b_i ~ Normal(mu_难度档位, sigma_b^2)
```

有足够作答数据时再校准题目参数。如果实际上只是固定标签映射、仅估 theta，就不要说已经联合估计了题目难度。

量尺也要有锚点：若 theta 和 b 同时增加一个常数，概率不变。联合估计时需约束能力分布、使用锚题等，否则数值难以比较。

#### MAP 怎么理解

MAP 全称 Maximum A Posteriori，即最大后验估计。设能力先验为均值 mu、方差 sigma² 的正态分布：

```text
theta_hat = argmax_theta [
    Σ_i { y_i*log(p_i) + (1-y_i)*log(1-p_i) }
    - (theta-mu)^2 / (2*sigma^2)
]
```

前半部分让能力解释实际对错；后半部分防止少量数据把能力推到极端。MAP 不是简单“做对加一分”。

固定难度时，还可用导数理解如何求解，不必背优化代码：

```text
一阶导 = Σ_i(y_i-p_i) - (theta-mu)/sigma^2
二阶导 = -Σ_i p_i*(1-p_i) - 1/sigma^2
```

直觉：实际表现比预测好，能力估计倾向于上升；证据少时，先验把它拉向合理范围。MAP 输出点估计，不自动等于完整的不确定性区间。

#### “动态估计”需要额外定义

新作答到来后重新估计 theta，可以称在线更新；但用所有历史拟合一个不变 theta，不自动等于建模了能力随时间变化。

设计可选近期窗口、旧证据衰减或显式时间状态模型，均要验证。若把旧后验作为新先验，就不能再把同一批旧数据完整加入似然，否则重复计数。

#### 选题算例

教学设定：theta=0.5，希望练习成功率约 0.7。

```text
theta-b = log(0.7/0.3) ≈ 0.847
b ≈ -0.347
```

因此练习题未必应该“难度最接近能力”。0.7 只是教学示例，不是普适最优阈值。

在这里固定区分度的 1PL 下，单题 Fisher 信息为 `p*(1-p)`，在 p=0.5 时最大。它解释的是测量能力的价值，不是教学增益最大。

#### 与 BKT 的冲突怎么处理

教学示例：整体能力较强，但分配律状态偏低。可先约束目标技能与先修关系，再选择不过难的题，必要时诊断。不能平均“0.3 的掌握概率”和“0.5 的能力值”，它们不是同一量纲。

经典 BKT 的同组 guess/slip 未显式区分每题难度；一直推难题，错误可能被归因为不掌握。仅加 IRT 选题并未消除这点。可分析难度分层误差，必要时研究题目相关观测参数等扩展；pyBKT 官方材料列有题目级 guess/slip 扩展。[S2]

### 7.4 候选编排：五路生成、过滤与排序

问题：只推最低掌握率知识点可能过度重复，且忽略先修和复习需要。

机制：不同教学意图分别生成候选，再统一合并与约束。

本方案落点：每路保留来源和可解释理由。以下策略细节均是对原描述的教学性设计展开。

| 路线 | 触发依据示例 | 目的 | 边界 |
| --- | --- | --- | --- |
| 弱项修复 | 掌握偏低且有有效证据 | 练当前薄弱技能 | 先验低不等于已诊断薄弱 |
| 先修回补 | 目标受阻且前置证据不足 | 补前置能力 | 先修图需要外部可信关系 |
| 间隔复习 | 到期、较久未独立练习 | 检查保持 | 不等于经典 BKT 有遗忘模型 |
| 相似错题 | 同类错因或题型错误 | 用变式检查纠正 | 文本相似不等于技能相同 |
| 自适应诊断 | 状态不确定或证据冲突 | 减少不确定性 | 诊断价值不是教学收益 |

“不确定性”必须说明对象：BKT 的二元状态接近 0.5、BKT 参数估计不稳、IRT 能力后验方差大，是三件不同的事。

#### 三个阶段

```text
召回：哪些题值得考虑？
过滤：哪些题不能发或当前不适合发？
排序：合格题里谁先发？
```

建议把教材版本、已学范围、题目有效性等视为硬约束；难度贴合、多样性和策略配额按产品定义作为软条件。初步过滤尽量早做，发题前复核易变约束。

候选不足时，按约定放宽软条件，不能为凑题放开超纲等硬限制。确实缺题时允许少发，并给出原因。

#### 三种去重

1. 跨路去重：同题被多路召回，保留一条候选、合并理由。
2. 近期去重：已曝光与已作答分别定义时间窗。
3. 内容去重：不同题目 ID 可能属于同模板，需额外簇标识或内容指纹。

永久禁止重复会与间隔复习冲突，应区分近期屏蔽和到期允许复习。

#### 规则排序示例

```text
score =
    弱项优先分 + 先修相关分 + 复习到期分
  + 当前任务相关分 + 诊断价值分
  - 难度不匹配惩罚 - 近期模板重复惩罚
```

它不是学习收益真值。分量要同尺度化，权重和配额要验证，硬约束不能被高分抵消。

#### 一个贯穿案例

学生把 `3(x-2)` 展开为 `3x-2`。可能是分配律薄弱，也可能粗心，不能一题定性。

设计链路：评分确认并去重事件；更新技能状态；必要时加入乘法先修诊断；在已学教材范围内找分配律变式；用能力匹配难度；排除刚做过的题和过近模板；返回理由“练习括号内每一项都乘系数”，而非“系统已确定你不会”。

### 7.5 缓存一致性：30 至 50 道候选池

问题：每次取题都重新生成候选可能成本偏高，预计算结果又可能过期。

机制：预存小批候选，用最终过滤、版本检查和异步补充平衡时效与成本。

本方案落点：30 至 50 来自原描述，是池容量，不是一次发题量，也不是 BKT 参数或已证明的最优值。

#### 数据职责

| 数据 | 建议保存内容 | 用途 |
| --- | --- | --- |
| 作答事实 | 原始事件、评分、时间、题目版本 | 持久化、回放、审计 |
| 学生状态 | 技能掌握概率、能力估计、版本 | 当前画像 |
| 候选池 | 有序题目 ID、来源、有效期、上下文版本 | 快速取候选 |
| 近期记录 | 题目 ID、曝光/作答时间 | 时间窗去重 |
| 刷新锁 | 持有者 token、租约 | 减少重复刷新 |

建议让作答事实进入持久化记录，不只保留在可丢失缓存里。

#### Fingerprint

设计示例：对规范化上下文生成摘要，内容包括画像修订号、教材与进度版本、题库版本、模型版本、策略版本、当前任务。

它回答“这批题是根据哪份上下文算的”，不提供原子性。字段顺序与缺省值要规范化。

每次作答都全部失效可能使缓存几乎无用；完全不失效又可能推旧题。可把教材变化、题目下架作为硬失效，轻微画像变化作为有时限且需重排的软过期。具体容忍范围要验证。

#### ZSet 时间窗

Redis 有序集合保存唯一 member 与可排序 score。[S4] 本方案可用题目 ID 作为 member、最近事件时间作为 score，查询窗口内记录并清理旧成员。

设计注意：整个 key 的 TTL 不是每个 member 的独立滑动过期；同题再次写入更新时间，不保留每次曝光历史。完整历史另存。候选排序分与近期时间分值建议用不同集合。

#### 刷新锁不等于正确性

租约锁通常需要原子获取、过期时间与唯一 token；释放时不能误删其他持有者的锁。[S5]

故障场景推演：

```text
A 获得锁，基于画像 v10 计算
A 太慢，锁到期
B 基于 v11 生成新池并写入
A 完成，如果直接覆盖，旧 v10 就覆盖了 v11
```

设计补充：原子条件提交检查上下文与生成版本；若需更强防护，使用单调 fencing token，并让写入方存储拒绝旧 token。只在客户端先检查版本再写仍存在竞态。

锁主要减少重复工作，条件提交防旧结果污染。二者不是替代关系。

#### 双端取题与事件重放

两个客户端都先查“没做过”，再各自返回同题，仍可能重复。可在同一原子边界执行最终检查、取题与写预占，并定义请求重试的幂等结果、未曝光预占的过期规则。

这是设计所需语义，不宣称已在任意部署拓扑中实现。具体 Redis 部署下还要确认多 key 原子操作范围。

作答回流也要按事件 ID 幂等，避免一次答案让 BKT/IRT 吸收两次证据。迟到事件不能随意追加到有序模型末尾，应有按序处理或回放约定。

#### 补池与降级

教学示例：低于 10 道时补到 40 道。这两个值都待调优。刷新任务可合并与有限重试；冷池使用轻量规则兜底；旧池只有通过当前硬约束检查才可短时使用。

### 7.6 效果验证：规则基线与 LambdaRank

问题：规则容易解释，但复杂交互靠人工权重难覆盖；学习排序又依赖可信标签。

机制：规则先作为可回退基线，有足够反馈后再研究请求内的相对排序。

本方案落点：原描述是“设计离线方案”，不意味着 LambdaRank 已训练或上线。

#### 先懂排序目标

LightGBM 的 LambdaRank 需要整数相关性标签，较高值代表更相关，label_gain 控制对应收益；排序样本需按 query group 组织。[S6]

直觉：把有价值题排到前面，比只调换两个无价值题更重要。算法不知道“学习”是什么，需要我们提供合适样本与标签。

一个待验证设计：以一次推荐决策作为组，组内是该上下文中有资格比较的题。不能把同学生跨学期所有题不加区分地当一个组。

建议特征：请求时掌握概率、能力难度差、预计成功率、证据量、先修关系、复习间隔、错因、候选来源、模板重复度。不能用答题后更新的掌握概率作为过去请求的特征。

#### 学习增益标签为什么难

下面是从数据可观察性出发的风险分析，不是已解决的训练流程：

1. 未选题没有真实作答反馈，不能直接设为差题。
2. 学生后续进步可能来自讲解或其他练习，不能直接归因一题。
3. 后续题难度不同，原始正确率不一定可比。
4. 没有后测是反馈缺失，不自动等于学习无效。
5. BKT 增量含证据修正和预设学习转移，不等于直接观测的真实增益。

一种可讨论的方向：在明确时间窗里，用同技能独立新题或校准后测形成收益，再映射为有序标签。但必须解决可比较性、归因范围与缺失反馈；不能随意给所有未选题补标签。

若数据尚不满足学习排序要求，继续用规则是合理结论，不是为了简历一定要训练。

#### 不要让模型自己证明自己

推理示例：若唯一目标是让 BKT 掌握度上涨，策略可能只学会让模型变乐观。可以把模型增量作为代理信号，但主验证应加入独立新题、延迟保持和迁移题，仍需处理因果归因。

旧策略决定哪些题被看到，训练数据会受选择影响。建议记录当时候选、位置、版本与选择概率，必要时开展受控探索；离线偏差校正依赖假设和覆盖性，不是万能补救。

建议先做离线回放与影子评估，再研究有护栏的对照实验。始终区分“计划怎样测”与“已经测出收益”。

## 8. 关键设计决策

| 决策 | 备选与取舍 | 风险 | 建议验证 |
| --- | --- | --- | --- |
| BKT 基线 | 对比近期正确率 | 假设不适合复杂题 | 未来作答预测与校准 |
| 组级共享 | 对比独立拟合 | 掩盖技能差异 | 按数据密度分层 |
| 标签初始化难度 | 对比直接视为真值 | 标尺不准 | 分档校准与锚题检查 |
| 规则先行 | 对比立即学习排序 | 人工权重有限 | 教师审查、独立后测 |
| 候选池预计算 | 对比实时轻量计算 | 过期和击穿 | 命中率、重复率、尾延迟 |
| 排序先离线 | 对比直接上线 | 标签与归因偏差 | 数据审计和受控实验 |

## 9. 量化与验证建议

所有实际指标均为待测。以下为建议评估设计，不是项目结果。

| 层级 | 怎样测 | 不能据此推出什么 |
| --- | --- | --- |
| BKT | 时间切分 LogLoss、Brier、AUC、校准，按稀疏度分析 | AUC 高不证明真实掌握准确 |
| IRT | 难度分档校准、独立题预测、不确定性 | 点估计不等于确定的能力等级 |
| 规则 | 超纲率、重复率、候选覆盖、教师抽检 | 满足规则不等于学得更好 |
| 排序 | 标签可信前提下 NDCG@K、未来特征审计 | NDCG 好不证明教学因果收益 |
| 教学 | 独立新题、延迟保持、迁移表现 | 当前正确率高可能只是题变简单 |
| 服务 | P95/P99、命中率、补池耗时、旧版本拒写率 | 没有实测不能编造下降幅度 |

验证集应守住时间边界；研究新学生泛化还需学生级留出；相似题和模板泄漏也要检查。候选、特征、标签、模型与策略版本应可追溯。
