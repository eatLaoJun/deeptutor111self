# Skill 示例：基于学情的例题分层讲解

更新日期：2026-10-09

> 本文为 `examples_and_exercises` 补充一份教学 Skill 规程示例。默认产物是教练端的讲解草稿，不直接接管学生端学习闭环，不安装或运行技能。
> 委派与执行背景见 [主 Agent 任务计划与四个子 Agent 委派示例](主Agent任务计划与四个子Agent委派示例.md)。字段与来源标识均用于讲解，不代表现有接口或真实学生记录。

## 1. 可以用 Skill，但它不是 Workflow 执行器

这个场景可以拆成：**子 Agent 完成例题任务，Skill 固化按学情讲解的方法，Tool 提供事实，Workflow 约束执行。**

| 部件 | 职责 |
| --- | --- |
| 角色 Prompt | 规定例题子 Agent 的任务边界、允许行为和输出契约 |
| Skill | 按需加载的教学方法：怎样拆解析、匹配学情、选择讲解层级和准备验证 |
| Tool | 查询题目、解析与已授权记录，或读取允许的 Skill；不凭文本自动产生权限 |
| 子 Agent Loop | 根据已有材料决定选哪道题、是否补查、怎样应用规程以及何时结束 |
| Workflow / 执行层 | 保证必要步骤与分支、校验输入输出，控制确认、等待、超时与预算 |

Skill 可以描述一个固定教学流程，也可以引用工具或流程入口；但写了步骤，不等于程序已经保证按顺序执行。需要强制验收、等待作答或状态推进时，仍由 Workflow / 执行层落实。

## 2. 输入不是只有解析和答案

建议的 Skill 标识为 `personalized_example_explanation`，仅为示意。

必要输入：题干、参考答案、解析与来源，当前教学目标、教材范围和本次希望生成的材料。

个性化还需要：与本题知识点相关的学生作答、近期验证结果或有效学情判断，保留来源、时间和适用范围。已有学习偏好可以调整表达方式，但不能替代掌握证据。

在当前备课链路里，这些材料优先从 C0、C1、C2 的可用结果中按需注入 C3，不复制全部学习历史。缺少证据时返回缺口，由主 Agent 决定补查或请教练补充；若角色本身已有授权查询工具，也只能在原权限和预算内读取。

**只有解析和答案时，Skill 能生成通用或条件分层草稿，不能凭空判断这个学生掌握到哪一步。** “上过课”不等于“已掌握”，背词表现也不能直接证明数学知识点的掌握情况。

## 3. 可加载的教学操作规程

### 3.1 适用条件

教练要求针对具体学生生成例题讲解，已有候选题与解析，但缺少按学情组织的讲解材料时使用。只需要展示原解析或读取答案时，不必加载完整规程。

### 3.2 固定步骤

1. **核对题目材料。** 检查题干、解析和答案是否对应，保留来源；发现疑点或矛盾先标记，不把参考解析自动当作正确结论。
2. **拆解知识点与关键步骤。** 提取解题所需的先修概念、关键转化和容易出错的环节，避免照搬整段解析。
3. **对齐学情证据。** 只使用与本题知识点相关、当前仍适用的材料，区分独立作答、提示后作答、历史事实和待验证判断。
4. **选择讲解策略。** 按下表形成有依据的讲解方案；掌握未知时不强行选定学生层级。
5. **生成讲解草稿。** 说明重点补哪一步、哪些内容可简略、准备怎样的提示或例子，并关联选择依据。
6. **准备理解验证。** 设计关键步骤检查题或变式练习，注明检查目的；生成检查题不等于学生已经通过，实际作答和状态推进交给课堂或既有学习 Workflow。

| 当前证据 | 草稿策略 |
| --- | --- |
| 先修概念存在已记录缺口 | 补概念、拆步骤，并安排基础检查 |
| 基础已具备，但关键转化出现问题 | 聚焦对应步骤的提示与解释，不重复整套基础讲解 |
| 有独立完成相关任务的有效证据 | 压缩已会部分，安排变式或迁移检查，不直接推断永久掌握 |
| 缺少、过期或矛盾的学情证据 | 标明未知，准备诊断问题或条件分层草稿，等待选择与验证 |

### 3.3 输出要求与权限边界

产物包括：例题引用、相关知识点、学情依据或缺口、讲解策略与草稿、验证计划，以及需要教练复核的内容。它可以嵌入 C3 的结构化结果，沿用主任务、计划版本与执行尝试的关联，不另建一份无关主任务。

- 不修改长期画像或自行更新知识点掌握概率。
- 不声称学生完成了尚未发生的验证。
- 不因 Skill 提到某工具就扩大角色白名单，也不在缺少授权时查询其他学生的记录。
- 不强制创建新的“Skill 执行 Agent”；Skill 默认由已有例题子 Agent 使用。
- 受当前子任务和父任务的轮次、截止时间与预算限制，不能通过“继续执行 Skill”绕过终止条件。

## 4. 只有解析和答案时的返回示例

以下只展示内容产物，外层任务关联仍由 Runtime 装配。来源标识为示例，实际必须解析到真实题目与解析。

```json
{
  "example_ref": "EX_Q1",
  "status": "partial",
  "mastery_evidence_status": "unknown",
  "student_evidence_refs": [],
  "explanation_mode": "conditional_drafts",
  "drafts": [
    {
      "condition": "若先修概念未掌握",
      "focus": "补充先修概念，并拆解关键步骤。"
    },
    {
      "condition": "若基础已具备但关键转化出错",
      "focus": "集中讲解对应转化，保留学生自主推导空间。"
    },
    {
      "condition": "若能独立完成相关任务",
      "focus": "简化重复讲解，准备变式迁移检查。"
    }
  ],
  "verification_plan": "在课堂先检查本题关键知识点，再选择合适的讲解层级。",
  "source_refs": ["EX_Q1", "SOL_Q1"],
  "gaps": ["缺少当前知识点的有效学情证据，以上为条件草稿而非已确认分层。"],
  "requires_teacher_review": true
}
```

这里标为 `partial`，因为“针对当前学生完成分层”仍缺少必要依据；已经有多份条件草稿，不代表个性化要求已满足。后续获得学情后可选择和修订草稿，不能把条件里的“若”改成学生事实。

## 5. 子 Agent 怎样加载并使用 Skill

执行层在允许的 Skill 目录中装配规程，或在角色已获得相应读取工具权限时允许按需加载。Skill 可以是 Markdown 操作规程，不必因为新增规程就引入一个执行框架。

```text
预定义例题角色 Prompt
    + 本次任务与输出要求
    + 按需加载的分层讲解 Skill
    + 题目、解析和相关学情证据
    ↓
examples_and_exercises 的独立 Agent Loop
    ↓
讲解草稿、选择依据、验证计划与信息缺口
    ↓
主 Agent 汇总到教案，教练审阅
```

固定的是教学规程；动态的是选题、依据选择、讲解深度和是否需要补查。若完整输入下只需一次模板化生成，主 Agent 直接应用 Skill 也可以，不必为了 Skill 再增加一次委派。

## 6. 什么时候需要程序化 Workflow

若业务要求每份讲解必须经过明确节点和验收，可以把规程落实成轻量 Workflow：

```text
材料核对 → 知识点拆解 → 学情证据检查
    ├─ 证据可用 → 生成针对性讲解草稿
    └─ 证据不足 → 诊断建议或条件草稿，标出缺口
    ↓
结果格式与引用校验 → 教学内容复核 → 回收草稿
```

Workflow 控制分支与验收，Skill 提供节点内的教学方法；输出结构和引用可做程序检查，内容正确性仍需语义评价与教练复核。若有真正的学生作答交互，等待、恢复和通过判定由既有学生端 Workflow 管理，不放进 Skill 文本里假装已经执行。

## 7. 面试表达

> 例题子 Agent 负责选题、取证和核对，我用 Skill 固化按学情生成讲解的方法：先拆知识点与关键步骤，再对齐学生证据，决定哪些内容补讲、哪些简略，并准备验证问题。Skill 是可复用的教学规程，不是调度器；固定节点和验收由 Workflow 控制，动态取证仍由 Agent Loop 处理。只有解析和答案时，我不会让模型编造掌握程度，而是输出条件草稿或诊断建议，补足证据后再完成个性化。
