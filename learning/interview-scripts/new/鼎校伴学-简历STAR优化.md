## 项目简介

鼎校伴学是面向 K12 学生的智能学习助手，以 Agent Runtime 串联多轮问答、工具调用、教材
检索和学习记忆，并通过结构化 Action 连接测评、试卷学情分析等业务。在既有能力基础上，
进一步设计错题与知识点辅导 Workflow，围绕错因诊断、教材讲解、针对性练习和理解验证
形成可追溯的学习过程。

## 1. Agent Runtime 与错题、知识点辅导 Workflow

### STAR 展开

- **S｜背景：** 一次性问答难以根据工具结果持续补充材料，也不能仅凭讲解结束判断学生理解；
  错题辅导需要协调模型分析、教材证据和多轮学生交互。
- **T｜任务：** 参与 Agent Runtime 执行链路建设，并在已有能力上设计受控的知识点学习流程。
- **A｜行动：** 基于 Agent Loop 串联模型决策、工具调用和结果回填，通过工具注册、参数注入、
  异步执行和异常回填统一接入能力；结合轮数限制、上下文裁剪和收尾策略控制执行。
  进一步设计外层 Workflow 管理诊断、讲解、练习、验证及有限补救，阶段内按需调用 Agent Loop；
  用明确任务状态表示等待和恢复位置，不依赖模型从聊天摘要推断进度。
- **R｜结果：** 原简历自述已形成多轮问答与工具执行闭环；新增 Workflow 部分的成果是分层方案、
  状态与异常边界设计，尚不能写成已上线的完整辅导闭环或学习效果提升。

### 简历精简版

**Agent 执行与学习流程设计：** 面向多轮问答和错题辅导，参与 Agent Runtime 建设，基于
Agent Loop、工具注册与结果回填形成受控执行闭环，统一处理工具异常、轮数预算和任务收尾；
在此基础上设计“诊断—讲解—练习—理解验证”Workflow，明确阶段推进、等待恢复与有限补救规则。

## 2. 分层记忆与上下文治理

### STAR 展开

- **S｜背景：** 长会话累计上下文增加输入开销，只保留近期对话又难以利用跨会话学习经历；
  简单摘要容易丢失来源，并把单次表现固化成长期标签。
- **T｜任务：** 设计可追溯的学习记忆与按阶段装配的上下文方案，兼顾个性化、证据和成本。
- **A｜行动：** 以 L1 保存或引用原始学习证据，L2 提炼场景事实，L3 归并带来源的画像项；
  按用户、知识点和时间选择相关历史，必要时回查原始作答。基于 UnifiedContext 组织近期
  对话、相关记忆、RAG 证据和工具结果，使用摘要与优先级裁剪控制输入；区分任务执行状态
  和学习经历，画像推断不直接代替本次诊断。
- **R｜结果：** 形成原始证据、场景事实、跨会话画像的分层设计和上下文治理方案；关系库画像项、
  自动归并及知识点关联查询按实际实现进度表述。原简历的 Token 和记忆命中指标需原始记录支持。

### 简历精简版

**分层记忆与上下文治理：** 针对长会话输入开销及跨会话信息缺失，设计 L1 原始证据、L2
场景事实、L3 用户画像体系，保留来源并区分事实与推断；基于 UnifiedContext 按任务装配
历史、画像和检索证据，结合摘要压缩与优先级裁剪控制上下文规模，为连续辅导提供可追溯的历史参考。

## 3. 教材 RAG 与知识覆盖优化

### STAR 展开

- **S｜背景：** 教材按章节组织，而学生常按细粒度知识点提问；检索不到答案可能来自材料缺失、
  版本或标签错误，也可能是已有证据没有被正确召回。
- **T｜任务：** 围绕本人参与的教材清洗、结构化及知识覆盖问题分析，改善可供检索使用的证据质量；
  向量入库与索引建设由对应同事负责。
- **A｜行动：** 整理教材正文、章节、页码和版本信息；对失败问题检查候选内容能否支持答案，
  区分缺材料、切块不完整、标签错误和排序问题；对只有例句、缺乏规则解释的知识点，反馈
  教研补充专题材料，配合索引负责人更新知识库，并按实际参与程度说明回归检查工作。
- **R｜结果：** 形成从失败问题定位到教研内容补齐的改进路径；不把语料补齐的收益写成独立算法
  调优收益，不把整套 Dense、BM25、RRF 和重排实现归为个人贡献。

### 简历精简版

**教材证据治理与知识覆盖优化：** 针对章节化教材难以充分回答细粒度知识点问题，参与教材
清洗与结构化，整理版本、章节和页码等来源信息；分析检索失败案例，区分知识覆盖与检索链路
问题，反馈教研补充专题讲解并配合知识库更新，为教材问答提供更完整、可追溯的证据。

## 4. Action 学习服务入口与结果回流

### STAR 展开

- **S｜背景：** 对话可以理解学习诉求，但测评、试卷分析等能力由独立业务服务承接，需要将对话
  需求转换为可操作入口，而不是停留在文字推荐。
- **T｜任务：** 接入英语三合一、单词测评和试卷学情分析等业务，连接入口展示与学习结果回流。
- **A｜行动：** 根据用户需求生成结构化 Action，服务端校验业务类型和允许参数，前端展示入口；
  用户点击后进入对应业务，由业务服务执行任务，结果关联原会话回写，并供后续学习记忆更新使用。
- **R｜结果：** 原简历自述已形成对话到学习服务的入口链路和结果回流；入口曝光、点击率、
  任务完成率等指标需确认事件定义、统计区间和实验基线后使用。

### 简历精简版

**学习服务接入：** 针对对话与独立学习服务之间的衔接需求，通过结构化 Action 接入英语三合一、
单词测评和试卷学情分析入口，支持用户点击进入对应业务，并将任务结果回写会话，供后续辅导引用。

## 5. OCR 与多模态结构化

### STAR 展开

- **S｜背景：** 试卷、错题和作业图片包含手写、印刷混排及复杂版面，直接识别可能出现题目边界
  混乱、字段缺失和坐标错位，影响下游学习服务读取。
- **T｜任务：** 将 OCR 和多模态解析能力服务化，输出下游可消费的题目与版面结构。
- **A｜行动：** 原简历自述集成 PaddleOCR-VL、MinerU 和 Qwen-VL，结合 OpenCV 做图像预处理，
  通过 JSON Schema、字段归一化、清洗和有限重试处理结果，以 Redis/OSS 管理任务与产物。
  具体组件各自承担什么环节，应以本人真实调用链说明，不将所有模型写成每次都调用。
- **R｜结果：** 为试卷学情分析、错题归档等业务提供结构化输入；没有验证报告时，不宣称具体
  识别准确率或稳定性提升比例。Schema 通过只说明格式合规，不证明识别内容正确。

### 简历精简版

**OCR 与多模态接入：** 面向试卷和错题图片，参与 OCR、多模态解析与图像预处理，结合结构
校验和字段归一化输出题目、版面及坐标信息，为学情分析和错题归档提供结构化输入。

## 投递前需要核实的数字与职责

- 用户于 2026-09-14 最新明确的简历口径为约 6.6 万页、9.2 万 Chunk，替代旧 PDF 的
  18.2 万页、32 万 Chunk 及中间讨论数值。该规模为用户提供，未独立审计；教材本数不据此推算。
- 37% Token 降幅：明确对照方案、样本、Token 统计范围及是否固定模型与任务。
- 71% → 90%：明确跨会话问题集、指标定义、标注及实验产物，不能与任务完成率混用。
- 73% → 94% → 99%：核实检索改动、语料补齐和评测版本；“至少命中一条有效证据”与标准
  Recall@K 定义不同，需统一指标名称。
- Action 点击率“提升 22%”：确认是相对提升还是增加 22 个百分点；任务完成率需固定分母。
- Workflow、Subagent、分布式熔断、恢复和幂等：区分已实现、原型验证和设计方案。

结果不一定必须是百分比：有证据的模块交付、业务接入、设计产物也可以作为 R；但不能把
预期收益当成已实现结果。正式简历可使用精简版，面试追问再展开对应 STAR。
