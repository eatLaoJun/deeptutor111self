# 鼎校伴学项目介绍

## 介绍主线与事实边界

不要按文件名或八股知识点逐一介绍，统一主线为：面向 K12 的学习助手，以 Agent Runtime
连接教材与题库能力，再通过学习工作流和带证据的记忆，把一次问答延伸为可验证的辅导任务。

本目录的知识点学习闭环、跨进程恢复和画像表结构明确属于设计材料，不能整体改写成上线经历。
用户参与范围以实际经历为准；RAG 材料明确向量入库不是本人完成。主介绍不使用尚未核实的
效果数字、索引参数和吞吐数据，不把最近讨论的 Redis 熔断、Celery 等补充方案列为已有技术栈。

## 两到三分钟介绍范例

我参与的鼎校伴学是面向 K12 学生的智能学习助手，围绕教材问答、题目讲解和学习记录提供服务。
我们希望解决的不只是生成一个答案，还包括回答有没有教材依据，以及后续辅导能否利用学生
之前的学习情况。

介绍技术工作时，我会重点展开 Agent Runtime 和上下文、记忆这条主线，具体承担到设计、
实现还是接入哪一层，按真实职责说明。Runtime 将用户问题和当前上下文交给模型，模型选择
工具后由程序执行，再把实际结果回填，形成受控的 Agent Loop。不是每个请求都启动复杂循环，
信息充分时可以直接回答，需要教材或题库信息时才调用对应工具。

教材 RAG 提供带版本、章节和页码的证据。我参与的部分要与索引建设区分；可以重点讲教材
清洗和知识覆盖问题的分析，比如有的材料只包含语法例句，却不足以解释规则。这种情况需要
反馈教研补充内容，不是单纯调整检索参数就能解决，向量入库由对应同事负责。

在这些能力基础上，我进一步设计了知识点学习工作流，让学生从一道错题进入诊断、讲解、
练习和理解验证。例如学生把 3(x-2) 写成 3x-2，先提出漏乘的候选错因并追问，再结合教材
讲解，使用新题验证。如果仍未达标，进行有上限的补救，而不是无限出题。

架构上是外层工作流管理阶段和等待点，内层按需使用 Agent Loop 做动态检索与讲解。学生
暂停后恢复要读取任务状态，不能靠模型从聊天摘要猜进度。学习经历则用三层记忆组织：L1
保留原始证据，L2 提炼一次学习中的事实，L3 形成带来源、可更新的画像，支持下一次辅导。
这部分按设计或验证进度说明，不把所有机制都说成已上线。

这套方案的重点是把模型的灵活分析放在程序约束中：模型提出错因和行动候选，程序校验工具
结果和状态推进，让教学证据、执行进度和长期画像各自有明确职责。

## 讲述取舍

- 开场先讲用户与问题，再讲实际职责；不要先背组件名或宣称整条链路都是个人实现。
- 已有能力与演进方案用“在此基础上，我进一步设计……”明确过渡。
- 三个深入方向：Runtime 执行闭环、Workflow 与 Memory 边界、教材证据覆盖问题。
- 准备具体例子而非堆工具名；SSE、Redis、HNSW 等留到相关追问，未落地就说设计方案。
- 结果优先陈述可证实的产物与能力，不把“达成本次学习目标”夸大为“长期掌握或成绩提升”。
