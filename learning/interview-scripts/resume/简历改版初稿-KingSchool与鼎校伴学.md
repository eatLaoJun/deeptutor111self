## 一、KingSchool 教练端智能助手（新增）

**标题：** KingSchool 教练端智能助手｜轻量 Agent Harness 与规划式备课

**项目时间：**【待确认：起止时间，是否与鼎校伴学并行】

**技术栈：** Python、AsyncIO、FastAPI、LangGraph、Plan-and-Execute、LLM Function Calling、RAG

**项目简介：**

为 KingSchool 教练端建设可插拔的 Agent 任务运行底座。首个能力为产品使用指引，帮助新教练了解功能用途、定位入口并完成操作；随后接入专题研究与备课助手，将教材检索、例题选择与教案生成组织为可追踪的长任务。两类业务复用同一套上下文装配、工具治理与运行记录，各自保留独立流程与验收规则。

**责任描述：**

### 1. 可插拔运行底座

- **两级扩展协议：** 定义 Tool / Capability 协议。Tool 声明输入 Schema、权限范围、超时与副作用标记；Capability 声明输入输出 Schema、依赖工具、工作流入口与预算默认值。新增业务按协议注册，不改动底座代码。
- **权限边界：** 工具鉴权置于执行端而非 Prompt 约束，模型无法通过参数覆盖可信身份与数据范围；教材检索限定版本学段，学情查询限定已授权班级。不做插件市场与第三方代码执行，可插拔仅覆盖"按统一协议接入"。

### 2. LangGraph 规划式备课编排

- **Plan-and-Execute：** 需求澄清 → 生成结构化计划 → 教练确认或修改 → 执行研究子任务 → 证据覆盖校验 → 有限补查 → 产出待审材料。动态的是计划内容与子任务集合，权限与执行边界不随模型输出变化。
- **人工确认一致性：** 确认绑定任务标识与计划版本，过期确认直接拒绝；计划修改后重新评估旧子任务结果是否有效，避免新旧计划结果混合；等待反馈时结束当前请求，后续按任务标识恢复。
- **分层职责：** LangGraph 管业务图状态与流转，Harness 管身份、数据权限、工具策略、任务入口与观测，不重复实现检查点引擎。

### 3. 长任务恢复与执行治理

- **恢复与幂等：** 状态持久化后支持重启恢复，恢复涉及节点重放，故对写入与发布类操作设计幂等键去重；区分"执行进度"与"长期用户记忆"，不把原始资料复制进共享状态。
- **预算与失败分级：** 设定任务/工具超时、最大补查次数与调用预算，触达边界返回部分结果并标明证据缺口；按参数错误、权限错误、临时网络错误、业务无结果分类，仅对幂等可恢复错误重试。
- **可观测性：** 记录任务与子任务标识、阶段变化、工具耗时与调用状态、模型用量及证据引用，日志剔除不必要的学生个人信息。

**【待确认】** 面试前补齐：checkpoint 后端、持久化与部署配置、本人负责模块、计划修改前后产物对比。按已实现状态描述，测试覆盖以实际记录为准。

## 二、鼎校甄选-鼎校伴学（替换原段落）

**项目时间：** 2025年09月 - 至今

**技术栈：** Python、AsyncIO、FastAPI、LLM Function Calling、Qdrant、BM25、Rerank、MySQL、Redis、OCR / 多模态模型

**项目简介：**

面向 K12 教育产品建设统一 Agent 交互入口，整合教材检索、题库与学习记忆，支撑多轮问答及错题、知识点讲解；以结构化 Action 连接测评与试卷学情分析等业务，将单次讲解延伸为"诊断—练习—理解验证"相衔接的学习任务。

**责任描述：**

### 1. Agent Loop 收敛与工具失败隔离

- **收敛边界：** 负责执行收敛策略。多轮工具调用下模型易反复检索而不给结论，通过轮次上限、上下文裁剪与 Forced Finish 三层约束：达到上限时强制进入总结分支，基于已有证据输出结论并标注未解决部分，而非截断请求或返回空响应。
- **失败隔离：** 以 Tool Registry / ToolResult 统一工具注册、参数注入与异步执行，工具超时或异常收敛为结构化失败结果回填模型，由模型改写参数、换工具或说明信息不足，避免单次工具失败中断整轮对话。
- **可追溯：** 统一 Trace 关联同轮内模型与工具调用，区分"模型选错工具"与"工具本身失败"两类问题。

### 2. 教学 Workflow：把讲解变成可验证的学习任务

- **问题：** 纯对话讲解无法确认学生真的理解，模型在学生回复"懂了"后就结束。据教研流程设计"错因诊断—针对性讲解—练习—复述与理解验证"Workflow。
- **分层编排：** 外层管阶段推进、等待作答与有限补救次数，内层按需调用 Agent Loop 完成单阶段的检索与讲解，即固定教学流程包裹动态工具决策。
- **通过判定与边界：** 以作答结果与复述内容作为阶段通过依据，而非对话轮数或学生自述；补救次数有上限，连续未通过转为标记薄弱点并给出后续建议，不无限重复讲解。

### 3. 分层记忆与跨会话召回

- **分层设计：** L1 信息提取与标签标注、L2 任务级记忆、L3 用户画像。L1 保留原始证据，L2 沉淀任务级场景事实，L3 增量维护画像；仅更新本次涉及的知识点与偏好，新旧证据冲突时结合来源与时间处理，保留证据关联支持追溯。
- **检索与评测：** L2 向量存储结合用户、知识点元数据过滤，支撑跨会话经历召回。130 个真实业务测试场景中 120 个成功召回所需历史记忆，成功率 92.3%；未召回场景区分"记忆未写入"与"检索未命中"分别处理。
- **上下文装配：** 基于 UnifiedContext 按任务装配近期对话、相关记忆、教材证据与工具结果，通过摘要压缩与优先级裁剪控制输入规模，使 10 轮以上长会话的单次调用平均输入 Token 降低约三分之一【待确认：原 37% 需说明基线、样本范围与质量对照，无记录则保留模糊表述】；学习记忆与任务执行状态分离存储。

### 4. 教材 RAG 与知识覆盖补齐

- **结构化切块：** 参与约 6.6 万页教材清洗与结构化，依托教研章节知识点树组织切块，协作形成约 9.2 万个 Chunk；跨块保留知识点关联及版本、章节、页码元数据，支持范围过滤与来源追溯。
- **混合检索：** 参与 Dense Embedding + BM25 双路检索方案设计，经 RRF 融合去重与 Rerank 语义重排选取 Top 10 证据。
- **失败归因（本人负责）：** 区分"库内已有证据未召回"与"教材缺少充分讲解"：前者定位切块粒度或查询表述，后者反馈教研补充细粒度材料并配合回归验证。该区分避免把内容缺口误判为检索效果问题。

### 5. 学情建模与自适应测评

- **知识追踪推题：** 基于 BKT 更新知识点掌握概率，结合薄弱点、题目难度与教材进度设计选题策略；为避免每次请求实时计算难度匹配的延迟，采用 Redis 候选池预构建 + 异步补池支撑在线推题。
- **词汇测评：** 基于 Rasch 模型与贝叶斯 EAP 估计词汇能力，按作答动态调整难度，结合估计误差设置停止条件，分段映射输出词汇量估计。

### 6. 业务接入与文档解析

- 返回结构化 Action 连接英语三合一、单词测评与试卷学情分析入口，任务结果关联原会话回写，打通需求识别、业务引导与结果回流。
- 接入 OCR 与多模态解析，结合 OpenCV 预处理、结构校验与字段归一化输出题目、版面及坐标信息；表格转 Markdown、图片存 OSS 并关联文本片段。
