# 面试前口述速记

[返回目录](README.md) | [完整问题索引](00_问题索引与复盘结论.md)

用途：复习时先脱稿回答，再看这份速记。原理不理解时回到三篇逐题解答，不只背结论。现场设计题的回答不等于你已做过该功能。

## 一、先统一答题方式

```text
先一句话回答问题
  -> 两三点解释机制
  -> 真实项目或明确标注的例子
  -> 边界与验证方式
```

被连续追问时，先停下来重述：

> 我理解您现在问的重点是【具体关注点】，不是【我刚才展开的话题】。我先直接回答这一点。

不确定的知识点这样处理：

> 这部分我没有深入到具体实现细节。我能确定的是【已知机制】，不确定的部分我不先下结论。

不要用“AI 时代不用学基础”解释，也不要为了接话补造框架能力或实测数字。

## 二、十四张口述卡

### 1. 我的技术路径

> 我本科是大数据管理与应用，学过 Python、Java 和数据结构。先做 Java 后端，再在工作中转向 AI 应用开发，现在主要用 Python，重点做鼎校伴学中的 Agent Runtime、Memory、RAG 和学习业务闭环。

### 2. GIL

> 传统 CPython 的 GIL 限制同一解释器里多个线程同时执行 Python 字节码，不代表只能开一个线程。I/O 等待可以用 AsyncIO 或线程实现并发；纯 Python CPU 密集计算通常考虑多进程或能释放 GIL 的扩展。具体还要说明解释器和构建版本，不能把所有 Python 都一概而论。

追问关键词：`async def` 不保证不阻塞；GIL 不代替业务锁；Worker 不等于无限并发。

### 3. 结构化输出可靠性

> 如果让我设计，我会先定义成功与时限，再用支持的结构化输出减少错误。返回后依次做 JSON 解析、Schema 校验和业务校验；可确定的问题本地处理，需要语义修正的才反馈模型，缺少事实就澄清。所有路径受总预算约束，成功率用实际统计验证，不靠“多试几次”承诺。

追问关键词：语法合法、Schema 合法、业务有效，是不同层次。

### 4. 本地修复 JSON

> 不需要每次都回模型。明确包裹可受控去除，格式问题可用理解 JSON 结构的解析或修复工具，而不是堆正则。但修复器也会猜，所以要保留原文、限制自动接受的范围，再做完整校验。补齐括号不代表补齐了被截断的业务数据。

追问关键词：别名必须预定义；关键字段不能随意默认；歧义与截断不自动放行。

### 5. 重试与 99.9%

> 三次尝试达到 99.9% 只是在每次失败率为 10% 且相互独立时的演算。真实错误往往相关，必须按错误分类处理并实测结果。限流用退避，内容错误用定向修正，缺信息用澄清；带副作用的重试还必须考虑幂等。

追问关键词：总共三次和重试三次不同；成功率 99% 不等于延迟 P99。

### 6. 自研和框架

> 核心业务编排和 Runtime 由我们自己建设，我参与了模型决策、工具执行、结果回填和异常收敛；基础 SDK、模型和检索组件则复用。LangGraph 本身支持持久化、循环和中断恢复，自研是业务契约与维护成本的取舍，不是因为框架不能跨轮。

追问关键词：不把 ReAct 当框架；不把多轮 Tool Calling 当独立 Planner。

### 7. 意图识别

> 我们没有额外前置调用一个分类模型，而是在 Agent Loop 中结合消息、上下文和可用工具完成任务理解。完整设计上还要明确任务类型、目标对象、必要条件和暂停取消等控制意图；缺信息就补槽位，有歧义就澄清，运行时再校验对象与权限。

追问关键词：工具选择只是落点，不覆盖所有槽位与兜底问题。

### 8. 未知意图与跨轮任务

> 我会区分闲聊、缺信息、不支持和暂停取消。闲聊可以侧答但不推进原任务；控制意图按业务状态处理；不支持就说明边界。节点验收与意图识别分开，不能把跑题当作答错，也不能因为本轮回答结束就认为学习任务结束。

这里的完整兜底是参考设计，不新增已有分支实施经历。

### 9. 三层 Memory

> 我实现的是原始证据、场景记忆和综合用户模型三层。L1 保留事件依据，L2 汇总一组任务事件并关联来源，L3 用当前画像和新增 L2 增量归并。近期原始对话另外保留，用于局部指代；画像服务跨会话，不替代历史，也不把一次表现贴成永久标签。

追问关键词：三层不是三个时间窗口；保存不等于运行时已经召回。

### 10. BKT

> 我用经典 BKT 更新知识点掌握状态，它是概率模型，可以表示为两状态 HMM，不是神经网络。四参数是初始掌握、学习转移、猜测和失误；线上先做观测更新，再考虑学习转移，离线估参数与线上个人状态递推分开。EM 是常见参数估计方法，不是模型类别。

追问关键词：掌握概率不等于下一题答对率；无遗忘不代表后验只能上涨；复述通过不直接覆盖 BKT。

### 11. 记忆冲突

> 先确认是不是同一对象、同一事件，再区分更正、现实变化和无法核实的冲突。保留来源并澄清，确认后更新当前结论；没核实时标为待确认。最新和重复最多都不自动代表真实，系统也不能凭两条错误日期猜出第三个正确日期。

追问关键词：时间衰减用于使用优先级，不直接裁决真伪。

### 12. Embedding 与 Reranker

> 典型 Bi-Encoder 分别编码 Query 和文档，文档向量可离线计算，再用索引检索。典型联合评分 Reranker 把 Query 和候选一起输入，判断更细，但通常需要对候选逐一打分，所以先召回再精排。小集合也可以直接全量重排，本地部署仍有算力、吞吐和时延约束。

追问关键词：模型大小不是定义；没进候选的文档通常无法靠精排找回；不是所有重排模型都长得一样。

### 13. 陌生业务方案

> 我先确认输入输出契约、硬规则和审核要求，再把已有记录校验与新记录生成分开。RAG 提供依据，模型理解需求和辅助生成，规则服务负责可执行约束；两条链路共用内部模型和确定性校验，通过后再序列化为 XML。规则或事实不足时返回无法判断，不编一个看起来合法的结果。

追问关键词：Top K 检索不保证约束齐全；大批量明细交给程序处理；JSON 合法不等于 XML 契约和业务都合法。

### 14. 私有化与国产硬件

> 按本次经历，我接触过 H100 环境，但没有独立做过国产加速卡适配。模型权重类似不代表软件栈相同，迁移要检查硬件后端、驱动、算子、精度和推理框架兼容，再验证业务质量与性能。我会讲清实际负责的部分，不用一条启动命令概括全部部署能力。

具体部署框架、模型和配置，应先补齐真实事实卡，不能根据含糊转写猜名称。

## 三、下次不要再说的几句话

| 不准确或容易跑题的表述 | 改成什么 |
| --- | --- |
| Python 只有一个线程池 | 传统 CPython 的字节码并行受 GIL 约束，线程和线程池都可以有 |
| 加上 JSON Schema 就一定 99% | 结构约束降低风险，交付仍需多层校验与实际测量 |
| 多试三次就能保证 99.9% | 独立性等假设不成立时不能这样承诺 |
| 格式不对就继续调模型 | 先判断能否确定性本地处理，必要时才语义修正 |
| LangGraph 就是固定 DAG，不能跨轮 | 它有循环、持久化与中断；自研说明业务取舍 |
| 没识别到就让模型自由发挥 | 缺信息、歧义、闲聊、不支持和控制意图分别处理 |
| BKT 是基于 EM 的神经网络 | BKT 是概率/HMM 模型，EM 是参数估计算法 |
| 后说的事实权重高，直接覆盖 | 对齐来源、对象和有效时间，必要时澄清 |
| 本地模型不考虑成本 | 仍受算力、吞吐、显存和时延预算约束 |
| 新业务先搭向量库和多租户 | 先确认目标、硬约束和契约，再选技术 |
| 国产卡和 H100 差不多 | 权重可相似，硬件运行栈和兼容性要单独验证 |

## 四、五道脱稿自测

### A. JSON：在 90 秒内说清处理顺序

输出有额外文本、尾逗号、缺少业务必填字段，还收到过一次 429。你分别怎么处理？

检查：是否先分类，是否说明本地修复边界，是否把 429 和内容修正分开，是否有总预算和失败出口。

### B. Agent：不要再绕回 Skill 名称

用户说：“这题先别做了，刚才那句话什么意思？”你提取哪些要素，原任务如何处理？

检查：是否识别暂停、指代对象和新问题；是否保持业务状态一致；是否避免把它算成错误作答。

### C. Memory 与 BKT：分清两类问题

学生先错后对又错，和开学日期前后矛盾，为什么不能用同一套“最新覆盖”逻辑处理？

检查：是否区分有噪声观测下的状态估计与事实证据冲突；是否知道无遗忘的 BKT 后验也能下降。

### D. RAG：不只说“召回、精排”

不用模型参数大小解释，讲清为什么文档向量能离线复用，而 Query-Doc 的最终重排分数一般不能预先算完。

检查：是否讲到输入方式、Query 条件化和计算规模；是否承认小集合可直接重排。

### E. 现场方案：先说需求，不先报技术栈

输入异构规则文档和已有 XML，还需要根据自然语言生成新 XML。先提出三个关键澄清问题，再讲两条链路。

检查：是否有规则审核、完整适用规则、可信事实、类型化中间对象、最终验证和不可行出口。

**练习通过的标准不是“背完了”，而是被打断追问后，仍能围绕当前问题直接作答。**
