## 可直接替换版

### 广汽埃安数字化平台｜Java 后端开发｜2023.07—2025.08

**技术栈：** Java、Spring Boot、Spring Cloud、MyBatis、MySQL、Redis、RocketMQ、Python、FastAPI、LLM、RAG

**项目简介：** 参与广汽埃安 APP 核心业务及企业 AI 应用平台建设，工作重心为 APP 侧车辆绑定、预约维保、服务点评和线索发送等模块，负责并发一致性、接口性能、消息可靠性及线上问题治理；同时参与 TMAP 的 Prompt、会话与知识库能力建设。

#### 1. APP 核心业务与分布式一致性

- 负责车辆绑定/解绑、预约维保、服务点评等核心需求开发及技术文档编写，参与从需求分析、方案设计到上线验证的完整交付过程。
- 参与 Redis 分布式锁的多轮迭代，解决重复提交等并发问题；参与分布式事务方案设计与落地，保障跨服务业务操作的数据一致性。

#### 2. SQL 与接口性能治理

- 负责慢 SQL 和核心接口优化，结合执行计划定位车辆管理接口中的模糊查询、SQL 函数导致的索引失效问题，通过查询改写和索引调整改善执行效率。
- 优化问卷投放及用户同步日志查询中的深度分页问题，减少大偏移量扫描对数据库和接口响应的影响。

#### 3. 异步链路与线上故障治理

- 参与线索发送链路优化，通过异步化与异常补偿降低第三方系统不稳定带来的接口长耗时和线索丢失风险。
- 独立定位优化上线后出现的 RocketMQ 消息积压问题，排查消息生产、消费及下游依赖链路并完成修复，具备生产环境故障分析和闭环处理经验。

#### 4. 企业 AI 平台工程化（TMAP）

- 参与 TMAP 企业 AI 平台建设，设计 Prompt 注册、动态匹配和延迟加载机制，统一管理 **20+ AI 对话场景**并使系统启动性能提升约 **60%**；同时参与会话存储抽象及 Query Rewrite 等知识库检索能力建设。

## 为什么这样排序

- 前三个节点全部来自 APP：先展示业务交付和一致性，再展示数据库性能与生产故障治理。
- SQL 使用车辆管理、问卷投放和用户同步日志三个具体案例，避免只写笼统的“做过 SQL 优化”。
- RocketMQ 强调独立定位和闭环解决线上积压，体现生产环境责任边界。
- TMAP 压缩为一个节点，只保留 `20+ 场景`、`启动性能提升 60%`及会话/RAG 平台能力，不与 APP 主线争夺篇幅。

## 建议准备的真实指标

如果能从监控、数据库或工单中找到数据，优先补充以下四类指标：

- 核心接口峰值 QPS、P95 延迟及错误率。
- 慢 SQL 优化前后的扫描行数、执行时间或慢查询数量。
- RocketMQ 最大积压量、恢复耗时、重复消费率或补偿成功率。
- 车辆绑定、预约维保的调用量、成功率或线上故障下降情况。

没有监控依据时，不要编写具体 QPS、延迟或故障下降比例；工程能力可以通过问题类型、定位方法、架构方案和责任边界体现。
