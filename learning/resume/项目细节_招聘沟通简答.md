# 三个项目的招聘沟通简答

您好，可以的。我主要做 AI 应用后端和 Agent/RAG 工程化，三个项目分别对应教育辅导、研发提效和企业知识与数据问答。

## 1. 核心职责、适用人群与落地效果

- **鼎校伴学：** 面向 K12 学生及教练，我负责学习流程编排、Agent 工具调用链路、上下文与分层记忆，参与教材 RAG 和业务接入。落地后的迭代重点是讲解有教材依据、跨会话衔接历史，以及通过作答验证理解；记忆模块在 130 个业务测试场景中成功召回 120 个，成功率 92.3%。这是业务场景测试结果，不是用户满意度。
- **ForgePilot：** 面向研发工程师，我重点负责上下文压缩、长任务状态与恢复机制，以及 PR Review 和修复效果评估。平台已供 500+ 名工程师使用；2026 年 Q2 组内累计修复 71 个 Bug，单个 Bug 平均处理时间由 178 分钟缩短至 53 分钟，降低约 70%，最终 PR 仍由人工审核。
- **TMAP：** 面向企业员工及 ESG 分析业务，我负责知识库/数据库 Agent 适配、组织资源路由、Prompt 与会话管理，并参与查询重写和 ESG 分析。核心价值是把分散的文档和业务数据统一到对话查询入口，检索侧主要围绕多轮意图补全和漏召回持续迭代。

## 2. 规划、记忆与 RAG 的设计及难点

- **任务规划：** 鼎校伴学采用外层 Workflow 控制阶段和验收，阶段内用 Agent Loop 动态调用工具。难点是任务跨多轮且不能无限执行，因此持久化状态与版本，用轮次和重试预算约束推进；ForgePilot 同样把修复、验证和交付拆为受控阶段，恢复前核对工作区与外部操作结果，避免重复副作用。
- **记忆：** L1 保留原始证据，L2 提炼场景事实，L3 增量更新画像，检索结合用户和知识点过滤。重点解决来源追溯、新旧证据冲突，以及区分“没有写入记忆”和“检索未命中”；学习记忆与任务执行状态分开，不能靠聊天摘要恢复任务。
- **RAG：** 教材按版本、章节和页码组织，采用 Dense + BM25、RRF 融合和 Rerank；TMAP 通过多查询改写及文档块假设性问题缓解表达差异。难点是区分“库里有但没召回”和“内容本身不足”，分别调整检索链路或反馈教研补齐材料。

## 3. LLMOps、API 集成调优与框架使用

我的实践主要在应用侧的模型接入、可观测性和效果迭代：参与多模型 API 适配，统一消息、工具调用和流式输出，处理超时、异常回填及有限重试；按场景、语言和模型管理 Prompt，结合调用轨迹、Token 统计和业务样本回归比较效果与成本。调优重点是上下文预算、检索证据和调用策略，不是从零预训练模型。

**LangChain 主要用在 TMAP 的模型与 Prompt 链路、数据库 Agent 业务适配。** 鼎校伴学和 ForgePilot 的核心执行流程按业务约束实现，不完全依赖框架默认链路。**LlamaIndex 不在这几个项目的主技术栈里，因此我不把它作为核心生产落地经验介绍。**
